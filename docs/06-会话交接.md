## 2. 关键设计决策与理由

新会话请**不要推翻这些决策**,除非用户明确要求;它们都是权衡后的结果。

### 2.1 AI 只写 `note.json`,不写 Markdown

让 AI 直接写 Markdown 的话,"内容是否超出原文"无法机械校验 —— 自然语言里没有
可检查的结构。改成让 AI 产出受 JSON Schema 约束的结构化数据后:

- 每条知识点都能强制携带 `text_en_quote` + `page`,可逐条比对原文;
- 排版由模板统一,不同章节风格一致;
- AI 的输出面被收窄,不会跑偏成散文。

代价是 AI 要填一个较复杂的 JSON,所以任务包里提供了 `note.template.json` 骨架。

### 2.2 门禁必须**双向**约束

只查"有没有编造"是不够的 —— AI 会用"少写"来规避风险(只挑简单段落做)。
所以同时加了覆盖率下限:**少写触发 `X001`,多写触发 `T001`/`Q001`/`V001`**。

### 2.3 拓扑图标签走 `labels_seen` 通道

这是开发中发现的**真实设计缺陷**,值得记住:
PDF 里的拓扑图是图片,`R1`、`Gi0/1`、`10.0.0.0/24` **只存在于像素中,不在文本层**。
最初的 token 门禁会把 AI 对拓扑图的正常描述误判为臆想。

解决方案不是放宽门禁,而是给图内文字开一条**可审计的证据通道**:
AI 必须先看图,把读到的标签逐字登记进 `figures[].labels_seen`,登记过的才算合法证据;
开启 `figure_ocr` 后由程序自动核对(`G010`),未开启时在报告里列出供人工抽查(`G011`)。

### 2.4 动画用纯 Pillow 自绘,不用 Manim

Manim 需要 LaTeX 工具链,在 Windows 上安装成本高、失败率高,与"方案要能直接实施成功"
冲突。改为纯 Pillow 逐帧绘制 `packet_flow`,零外部依赖,同时输出
**动画 GIF + 分步静态图 PNG**(静态图保证打印/离线/任何阅读器都能看懂过程),
有 ffmpeg 时额外出 MP4。

### 2.5 所有外部工具都必须可降级

mermaid-cli / graphviz / ffmpeg / tesseract / 图像生成 API **全部可选**。
缺失时降级(内联代码块、跳过 MP4、跳过 OCR 核对、保留提示词)并在笔记里说明,
**绝不抛异常中断流水线**。改 `visuals.py` 时请保持这一点。

### 2.6 覆盖率只算正文页,不算测验页

否则 AI 可以只写第一小节,却让测验引用全部页码来凑覆盖率。
拆成 `body_pages()` / `quiz_pages()` 之后,还顺带得到了反超纲检查
`X011`(测验引用页必须 ⊆ 正文已讲页),正好对应用户"费曼问题不能超纲"的要求。

### 2.7 面试题放协议级,不放章节级

用户明确要求把面试相关内容放在"整个 OSPF / 整个 BGP 之后"。这个要求是对的:
单章素材太少,连环追问撑不起三层深度,场景题也没法跨章串联。
所以新增了 `groups` 阶段,按目录聚合成协议级复习笔记。

分组键默认取**最后一层目录**(`group_depth: 0`),即 `IGP/OSPF/xxx.pdf` → `IGP/OSPF`。
想按一级方向聚合就把 `group_depth` 设为 1。

### 2.8 "允许发散"如何与"不臆想"共存

这是本轮最需要想清楚的取舍。做法是**分栏 + 分级校验**:

- 核心答案字段(`answer_template_*` / `ideal_answer_*` / `layers[].answer_*` / `correct_*`)
  → 严格校验:必须有 `grounding`,且逐条与原文比对;token 也要有依据。
- `extension_zh` / `extension_en` → 完全不校验,但渲染成独立的
  「🔶 课程外扩展」区块,并在页首和附录声明"不属于课程内容"。

这样"发散"被允许,但**必须承认自己是发散** —— 读者永远能分清哪句是课程结论、
哪句是工程经验。`_iter_grounded_text()` 决定了哪些字段受约束,
改 `groups.py` 时**不要**把 `extension_*` 加进去,否则发散功能就废了。

### 2.9 "详尽扎实"用密度门禁来度量

"杜绝空洞概括"是个主观要求,必须转成可校验的指标,否则约束不住模型。
做法是 `X012` 知识点密度门禁(默认 ≥2.0 条/正文页)+ `points[].detail_zh`
深入说明 + 各字段长度下限。这样"写浅"和"写少"一样会被拦下。

### 2.10 自动撰写:质量靠门禁,不靠模型自觉

`nlnotes write` 把"写 → 校验 → 回灌 → 重写"自动化。关键认识是:
**门禁在本地跑、不花钱**,所以可以放心让模型重试。
质量下限由门禁决定,模型强弱只影响"重试几轮"和"中文顺不顺"。
这也是为什么用便宜模型也能得到可信笔记。

这个闭环有自测覆盖:`tests/mock_llm_server.py` 是一个假的 OpenAI 兼容服务,
第 1 轮故意返回带臆想的内容,验证门禁拦下 → 错误回灌 → 第 2 轮通过。
**不需要任何 API Key,不花一分钱。**

### 2.12 Gemini 能写笔记,Cursor Grok 4.6 没有 Key

用户问过"我有 Google Gemini / Cursor Grok 4.6,怎么拿到 Key"。结论要写死:

- **Gemini App / Gemini Advanced ≠ API Key**。可编程 Key 只来自
  Google AI Studio(`https://aistudio.google.com/apikey`)。
  写笔记走官方 OpenAI 兼容端点
  `https://generativelanguage.googleapis.com/v1beta/openai`,
  仍然放进 `NLNOTES_API_KEY`。`GEMINI_API_KEY` 只给可选示意图用。
- **Cursor 里的 Grok 4.6 没有可提取的 Key**,不能填进 `NLNOTES_API_KEY`。
  用法是会话批量写(`docs/08` + `prompts/60`)。xAI 控制台另卖的 Grok API
  跟 Cursor 订阅不是一回事。
- `test-key-1234` 得到 HTTP 401 表示**网络通、Key 假**,不是工具坏了。

## 3. 开发中修过的坑(不要重新踩)

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| Jinja `trim_blocks` 吃换行 | 术语表所有行挤成一行;费曼题目之间没有空行 | 内容行不以 `{% %}` 结尾;改用 `pages_fmt` / `codes` 过滤器,表格在 Python 里拼好 |
| 术语表短缩写误命中 | `Administrative Distance`(别名 `AD`)命中 `address`;`AS` 命中 `such as`;`TE` 命中 `state` | `evidence.py` 加词边界匹配;`len<=4` 且全大写的缩写改为**大小写敏感** |
| 组合词被判无依据 | `DR/BDR` 整体查不到(原文是分开的 `DR` 和 `BDR`) | token 检查失败时按 `/ - _` 拆开,每段都有依据即通过 |
| IP 白名单没生效 | `labels_seen` 里登记的 `192.168.12.0/24` 仍被 `T001` 报错 | `TOKEN_IP` 分支漏了查白名单,补上 |
| `StrictUndefined` 崩模板 | `'dict object' has no attribute 'intro_zh'` | `assemble._normalize()` 补齐所有可选字段默认值 |
| `jsonschema` 未安装被静默跳过 | 结构门禁形同不存在,自测却"通过" | 装上并加了"结构里出现未定义字段"反例;`doctor` 会检查该依赖 |
| PowerShell 函数返回值污染 | `(Invoke-NlNotes ...) -ne 0` 会把命令 stdout 一起当返回值 | 函数不返回值,调用后读 `$LASTEXITCODE` |
| bash 空数组 + `set -u` | 空数组展开出一个空串参数,argparse 报错;macOS 自带 bash 3.2 更严格 | 统一写成 `${ARR[@]+"${ARR[@]}"}` |
| `.gitignore` 误伤 | `notes/` 会匹配任意层级的 `notes` 目录,把 `examples/notes/` 也忽略了 | 改成 `/notes/` 只匹配根目录 |
| Debian 上 venv 创建失败 | `ensurepip is not available` | `sudo apt-get install -y python3.12-venv` |
| JSON fixture 里的中文引号 | 在 JSON 字符串值里直接写 ASCII `"` 会破坏 JSON,自动修复脚本反而把定界符也改坏了 | 写中文内容时**不要用引号**,改用顿号或直接省略;需要强调就加粗 |
| 面试笔记里 `R1`/网段被误判 | interview 的 token 白名单最初只有术语表,没带上各章 `labels_seen` | `groups.py` 里从各章 note.json 收集 `labels_seen` 并加入白名单 |
| dry-run 显示"失败 N" | dry-run 时 `passed` 恒为 False,摘要照抄了通过/失败口径 | `summarize()` 区分 dry-run 与实跑;dry-run 一律返回 0 |
| 覆盖度被测验页"顶"上去 | 把 must_master / difficulties 的页码也算进覆盖度,导致只写一节也能达标 | `body_pages()` 只算正文小节;费曼引用页归入 `quiz_pages()` 并受 `X011` 约束 |

## 4. 已知限制(不是 bug)

- **扫描件 PDF 不支持**:整页是一张图、没有文本层的 PDF 无法抽取原文,
  需用户先转成可搜索 PDF。抽取结果里 `char_count` 接近 0 就是这种情况。
- **Cloud VM 上没有真实课程目录**,只能用合成 PDF 验证工具链。
- **`extract` 目前串行**,几千个 PDF 需分批(按一级目录开多进程,`--path` 分工)。
- **门禁保证"没编造",保证不了"讲得好"** —— 中文是否顺畅、小节划分是否合理、
  自制图是否必要,仍需人工抽检(建议每 10~20 篇抽 1 篇)。

按"保留程度"从高到低,三条路:

注意:一旦发了 follow-up,Cloud Agent 就不再自动修 CI 失败了。

### 路线 B:搬到本地继续

在 Cursor 的 **Agents Window**(不是经典 Editor Window)里做 cloud → local 移交。
纯 git 层面也可以接手代码,但**对话历史不会跟过来**:

```powershell
git fetch origin cursor/networklessons-pdf-to-chinese-notes-pipeline-ec2b
git checkout cursor/networklessons-pdf-to-chinese-notes-pipeline-ec2b
```

本地 Chat 面板支持 **Fork**(整段复制,或从某条消息处复制),这是本地独有功能。
新会话里还可以用 `@Chats` 引用旧对话。

### 路线 C:开一个全新会话(本文件就是为此准备的)

新建 Cloud Agent 时把 `repos[].prUrl` 指向 PR #6 以继承**代码状态**,
然后把下面这段话作为首条消息 —— 它会让新会话继承**决策上下文**:

```
先读 AGENTS.md 和 docs/06-会话交接.md,再读 docs/00-总体方案.md。
这两个文件包含了此前所有的设计决策、踩过的坑和当前进度,
请以它们为准,不要推翻既有决策。

工作分支:cursor/networklessons-pdf-to-chinese-notes-pipeline-ec2b(PR #6)
环境准备:sudo apt-get install -y python3.12-venv && python3 -m venv .venv
          && .venv/bin/pip install -r requirements.txt
验收方式:.venv/bin/python tests/run_e2e.py 必须输出 ✅ 全部自测通过

我这次要做的是:<在这里写你的新需求>
```

如果新会话是 Cloud Agent 且你希望它读到**上一轮的完整对话记录**,再加一句:

```
另外,请用 Cursor Cloud MCP 的 batch-fetch-details 拉取
bc-1e3a3396-03a9-4f9f-ad0d-b0e03135ec2b 的 transcript,
了解上一轮会话的完整经过(transcript 很大,请用 subagent 读,不要直接读进上下文)。
```

### 路线 D:本机新开一个「只写笔记」的会话

如果目的不是改工具链,而是让 Grok 在本机继续写章节笔记:
**不要**把旧聊天或本文件贴进去,也**不要**把 `prompts/60-批量流水作业.md` 整份粘贴。
只复制该文件「第一节」的代码框。前提是本机已经跑过 `scan/extract/tasks`,
且 `nlnotes next --count 1` 能打出 id。详见该文件第 0 节。

### 无论走哪条路,以下内容都会被自动继承

- `AGENTS.md` —— Cloud Agent 与本地 Agent 都会自动读取;
- `.cursor/rules/nlnotes.mdc` —— `alwaysApply: true`,注入每个新会话;
- `prompts/` + `docs/` —— 写笔记的铁律、错误码改法、完整方案。

**所以真正需要做的是:每次会话结束前,把新的决策与坑补进本文件和 `AGENTS.md`。**
这比依赖聊天记录可靠得多,团队成员和后续 Agent 也都能读到。
