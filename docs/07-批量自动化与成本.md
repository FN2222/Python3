# 批量自动化与成本

> 回答一个核心问题:**把上千个 PDF 做成笔记,需不需要我一直盯着?要花多少钱?**

## 一、先分清两件事:哪些免费,哪些花钱

| 环节 | 谁在干活 | 是否消耗额度 |
| --- | --- | --- |
| `scan` 扫描目录树 | 本地 Python | **免费**,可无限跑 |
| `audit` PDF 体检 | 本地 Python(PyMuPDF) | **免费** |
| `extract` 抽原文/拓扑图/CLI 块 | 本地 Python | **免费** |
| `tasks` / `groups` 生成任务包 | 本地 Python | **免费** |
| **撰写 `note.json` / `interview.json`** | **大模型** | **只有这一步花钱** |
| `verify` 反臆想门禁(9 组 40+ 条) | 本地 Python | **免费** |
| `visuals` 动画 GIF / 分步静态图 / MP4 | 本地 Pillow + ffmpeg | **免费** |
| `assemble` 渲染 Markdown、拷贝资源 | 本地 Python | **免费** |
| `index` / `status` / `cost` | 本地 Python | **免费** |

也就是说:**整条流水线只有"写内容"这一步需要模型。**
其余全部是确定性代码,跑一万次也不花一分钱。

而"写内容"这一步有三种做法,费用差很多:

| 做法 | 是否需要人盯 | 花什么 |
| --- | --- | --- |
| A. Cursor 会话批量写 | 每 5 章发一次指令(见 [`prompts/60-批量流水作业.md`](../prompts/60-批量流水作业.md)) | Cursor 的请求额度 |
| B. **`nlnotes write` 自动跑** | **完全不需要**,一条命令跑完全部 | 你自己的 API Key 按 token 计费 |
| C. 本地模型(Ollama / vLLM) | 不需要 | 电费,但质量与速度需自行验证 |

> 公司网络会拦命令行 HTTPS 的话,B 可能连不上 API。**先探测一次再决定**:
>
> ```powershell
> $env:NLNOTES_API_KEY = "你的key"
> python -m nlnotes write --probe
> ```
>
> 它只发一个极短请求(几乎不花钱),然后明确告诉你是哪种情况:
> 连通正常 / Key 无效 / **公司网络 TLS 拦截(这条路走不通,改用 A)**。
>
> 注意 Key 必须是**纯 ASCII** —— 填了中文占位文字会报
> `'latin-1' codec can't encode characters`(HTTP 头只能是 ASCII)。

## 二、推荐做法:`nlnotes write` 全自动

### 它做什么

对每一章,循环做人工会做的同一件事,直到通过:

```
读任务包 -> 调模型产出 JSON -> 落盘 -> 跑 verify -> 把 errors 原样回灌 -> 重写
                                              ↑                            |
                                              └────── 最多 writer_max_rounds 轮 ──┘
```

**关键点:门禁在本地跑,不花钱。** 模型写错了会被本地代码抓住,
错误连同修复建议一起回灌给模型重写。所以质量不靠"模型很聪明",
而靠"本地校验很严格 + 允许重试"。

这个闭环有自测覆盖:`tests/run_e2e.py` 会启动一个本地假 LLM 服务,
第 1 轮故意返回带臆想的内容(编造定时器数值 + 改写原文引用),
验证门禁能拦下、错误能回灌、第 2 轮能通过 —— 全程不花一分钱。

### 配置

`config/pipeline.json` 里三项:

```json
{
  "writer_base_url": "https://api.deepseek.com/v1",
  "writer_model": "deepseek-chat",
  "writer_api_key_env": "NLNOTES_API_KEY"
}
```

任何**兼容 OpenAI Chat Completions 协议**的服务都能用,只改这两行:

| 服务 | `writer_base_url` | `writer_model` 示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里通义(兼容模式) | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |
| OpenRouter | `https://openrouter.ai/api/v1` | 任意模型名 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1` 等 |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:32b` |
| 本地 vLLM | `http://localhost:8000/v1` | 你部署的模型名 |

设置 Key(不要写进配置文件):

```powershell
$env:NLNOTES_API_KEY = "你的key"        # Windows PowerShell
```

```bash
export NLNOTES_API_KEY=你的key           # macOS / Linux
```

也可以用环境变量临时覆盖服务地址,方便切换:
`NLNOTES_WRITER_BASE_URL`、`NLNOTES_WRITER_MODEL`。

### 用法

```powershell
# 0) 先确认能连上(只发一个极短请求)
python -m nlnotes write --probe

# 1) 再估成本(不发任何请求)
python -m nlnotes write --dry-run

# 2) 小批量试跑,人工看效果
python -m nlnotes write --path OSPF --limit 3
python -m nlnotes build --path OSPF --limit 3

# 3) 确认效果 OK 后全量跑(可以睡觉去)
python -m nlnotes write

# 4) 章节写完后,生成协议级面试复习笔记
python -m nlnotes groups
python -m nlnotes write-group
python -m nlnotes build-group

# 5) 随时看花了多少
python -m nlnotes cost
```

`write` 会自动跳过已经通过校验的章节,所以中断后**直接重跑即可续上**,
不会重复花钱。

### 失败怎么办

`writer_max_rounds`(默认 4)轮还过不了的章节会被标记失败并继续下一章,
最后汇总失败清单。这些章节再单独处理:

```powershell
python -m nlnotes verify --id <pdf_id> --show     # 看具体卡在哪
python -m nlnotes write --id <pdf_id> --force     # 换个模型或重试
```

通常失败集中在两类 PDF 上:排版特别复杂的,和内容特别短的。
数量不会多,人工兜底成本可控。

## 三、成本怎么估

### 用工具自己算,不要猜

```powershell
python -m nlnotes write --dry-run
python -m nlnotes write-group --dry-run
```

输出示例(4 页的测试章节):

```
[预估] IGP/OSPF/OSPF Neighbor Adjacency.pdf — 输入约 8319 tok / 输出约 9000 tok / 约 $0.0121(单轮)

成本预估:1 个任务(其中 1 个需要调用模型,0 个已完成会跳过)
token:输入约 8,319 + 输出约 9,000
费用:约 $0.01(按单轮估算;实际平均 1~2 轮,请按 2 倍留出余量)
```

### 影响成本的三个量

1. **原文长度** —— 输入 token 的主要来源。10 页左右的章节,
   连同任务包(TASK.md + 图清单 + 术语表 + schema)大约 1.5 万~3 万输入 token。
2. **输出长度** —— 一份详尽的 `note.json` 大约 8 千~1.5 万输出 token。
   面试复习笔记更大,约 1.5 万~2.5 万。
3. **重试轮数** —— 门禁越严、模型越弱,轮数越多。实际平均 1~2 轮。
   **按 2 倍留余量估算比较稳。**

### 怎么把价格填对

`config/pipeline.json` 里这两项只用于**估算**,不影响实际扣费:

```json
{
  "writer_price_in_per_mtok": 0.27,
  "writer_price_out_per_mtok": 1.10
}
```

单位是**美元 / 百万 token**。请到你所用服务商的官方定价页抄最新数字填进来
(各家价格变动频繁,本文不列具体价格以免误导)。
填好后 `--dry-run` 和 `cost` 的数字才有意义。

### 一个数量级的判断

以"输入 2 万 + 输出 1.2 万 token、平均 1.5 轮"的章节为例,
乘以你所选模型的单价即可得到单章成本;再乘以章节数就是总成本。

经验上:**国内主流的性价比模型,单章成本通常在几分钱到几毛钱人民币这个量级;
旗舰模型会高出一个数量级。** 具体数字请用 `--dry-run` 按你的实际定价算。

### 省钱但不降质量的四个做法

1. **先小批试跑**:`--limit 3` 验证效果,再全量。避免用错配置白跑一遍。
2. **开启 `figure_ocr`**:OCR 把拓扑图里的文字提取到 `figures.md`,
   这样**纯文本模型也能填 `labels_seen`**,不必用更贵的多模态模型。
   → 这是性价比最高的一项优化。
3. **分层用模型**:章节笔记用性价比模型批量跑;
   协议级面试复习笔记数量少(一个协议一份)、要求高,可以单独用更强的模型:
   ```powershell
   python -m nlnotes write                     # 章节:便宜模型
   # 改 config 的 writer_model 为更强的模型,或用环境变量临时切换
   $env:NLNOTES_WRITER_MODEL = "更强的模型名"
   python -m nlnotes write-group               # 面试笔记:强模型
   ```
4. **不要为了省钱下调门禁阈值。** 阈值决定的是笔记可信度,不是成本。
   真正省钱的是"少重试",而少重试靠的是选对模型,不是放宽标准。

### 为什么不建议只图便宜用最弱的模型

门禁很严,弱模型会反复失败,重试轮数上去之后**总成本反而更高**,
而且失败章节需要人工兜底,人的时间比 token 贵得多。
建议用 `--limit 5` 分别试两三个模型,比较"通过率 / 平均轮数 / 单章成本",
再决定用哪个跑全量。`build/write-log.jsonl` 里有每章的实际数据,
`nlnotes cost` 会按模型汇总。

## 四、还需要我(AI 助手)介入吗

分三种情况:

| 场景 | 是否需要 |
| --- | --- |
| 批量把 PDF 做成笔记(包括面试复习笔记) | **不需要。** `nlnotes write` + `write-group` 全自动跑完 |
| 调整笔记风格 / 排版 / 门禁参数 | 需要一次性改 `templates/`、`prompts/`、`config/`,之后不需要 |
| 真实 PDF 排版特殊导致抽不到图或抽错 | 需要看一眼报告调抽取参数(一次性) |
| 反复失败的少数章节 | 需要人看报告判断(数量少) |
| 扩充术语表、增加新的可视化类型 | 按需 |

也就是说:**日常批量生产不需要我;只有调参和兜底需要。**

## 五、完整的全量制作步骤

```powershell
# ---------- 一次性准备 ----------
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m nlnotes init
#   编辑 config/pipeline.json:
#     "source_root": "D:/NetworkLessons/All-Courses-v3.0"
#     "font_path":   "C:/Windows/Fonts/msyh.ttc"
#     "figure_ocr":  true                    ← 建议开启(需装 tesseract)
#     "writer_base_url" / "writer_model"     ← 填你的模型服务
$env:NLNOTES_API_KEY = "你的key"

python -m nlnotes doctor                     # 体检

# ---------- 第 1 步:体检 PDF,剔除不可用的 ----------
python -m nlnotes scan
python -m nlnotes audit
#   看 build/audit.md:被剔除的 PDF 需要先 OCR 成可搜索 PDF 再放回

# ---------- 第 2 步:抽取 + 生成任务包 ----------
python -m nlnotes prepare

# ---------- 第 3 步:估成本 ----------
python -m nlnotes write --dry-run

# ---------- 第 4 步:小批试跑并人工验收 ----------
python -m nlnotes write --path OSPF --limit 3
python -m nlnotes build --path OSPF --limit 3
#   打开 notes/ 下的笔记看效果,不满意就调 prompts/ 或换模型,再重跑这一步

# ---------- 第 5 步:全量跑章节笔记 ----------
python -m nlnotes write                      # 可中断,重跑自动续上
python -m nlnotes build                      # 校验 + 渲染动画 + 出 Markdown

# ---------- 第 6 步:协议级面试复习笔记 ----------
python -m nlnotes groups                     # 按协议分组建任务包
python -m nlnotes write-group                # 自动撰写
python -m nlnotes build-group                # 校验 + 渲染

# ---------- 第 7 步:收尾 ----------
python -m nlnotes index                      # 重建 notes/README.md 导航
python -m nlnotes status --detail            # 看整体进度
python -m nlnotes cost                       # 看实际花费
```

Windows 一键脚本也可以:

```powershell
.\scripts\Run-Pipeline.ps1 -SourceRoot "D:\NetworkLessons\All-Courses-v3.0" -Install
.\scripts\Run-Pipeline.ps1 -BuildOnly
```

## 六、必须充值吗

不是必须,但**建议**:

- **不充值的路子**:用本地模型(Ollama + 一个 30B 级别的中文模型)。
  完全免费,但生成速度慢、通过率低、重试多,而且中文表达和英文原文的忠实度
  需要你自己抽检验证。适合先跑几章看看能不能接受。
- **充值的路子**:用性价比模型的 API。整套课程的总成本通常是一顿饭到几顿饭的量级
  (具体数字用 `--dry-run` 按你的实际定价算),换来的是不用管、通过率高、
  笔记质量稳定。

两条路的**质量下限是一样的** —— 因为质量由本地门禁把关,不由模型自觉。
模型更强只是"更少重试、表达更顺",不会突破门禁去写臆想内容。

## 七、常见问题

**Q:中途断网 / 中断了怎么办?**

直接重跑同样的命令。`write` 会跳过已通过校验的章节,不会重复花钱。

**Q:能并行加速吗?**

`write` 目前是串行的(也便于控制限流)。要加速可以按一级目录开多个终端:

```powershell
python -m nlnotes write --path Switching
python -m nlnotes write --path IGP
```

它们写入不同的 `build/tasks/<id>/OUTPUT/`,互不冲突。
注意别同时跑 `scan`(会并发写 `manifest.json`)。

**Q:限流报错怎么办?**

调大 `writer_sleep_between`(章节间隔秒数),或调小并行终端数。
`writer_retry_on_error` 默认会对 429/5xx 做指数退避重试。

**Q:模型输出被截断怎么办?**

调大 `writer_max_tokens`。详尽的 `note.json` 需要较大的输出上限,
默认 16000;面试复习笔记更大,必要时调到 24000 以上,
并确认所选模型支持这个输出长度。

**Q:怎么知道笔记质量没下降?**

看两处:`build/reports/<id>.json` 的 `stats`
(引用通过率、覆盖率、知识点密度、图引用数),以及 `nlnotes cost` 的平均轮数。
密度掉了、覆盖率贴着下限、轮数变多,都说明该换模型或调提示词了。
