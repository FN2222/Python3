# 流水线详解

## 命令总览

| 命令 | 作用 |
| --- | --- |
| `init` | 生成 `config/pipeline.json` |
| `doctor` | 体检:路径 / 依赖 / 字体 / 可选工具 |
| `scan` | 扫描课程目录树 → `build/manifest.json` |
| `extract` | 抽原文、拓扑图、CLI 块 → `build/extract/<id>/` |
| `tasks` | 生成 AI 任务包 → `build/tasks/<id>/` |
| `prepare` | `scan` + `extract` + `tasks` 一条龙 |
| `next` | 列出接下来该写哪几章 |
| `verify` | 只跑门禁,输出报告 |
| `assemble` | 只组装 Markdown(跳过门禁) |
| `build` | `verify` + 渲染可视化 + `assemble`(**日常用这个**) |
| `index` | 重建 `notes/README.md` |
| `status` | 查看整体进度 |
| `audit` | **PDF 体检**:可搜索性 / 扫描件 / 加密 / 乱码,三档分级并自动剔除 |
| `diag` | 把环境 / 目录概况 / 体检汇总 / 抽取质量 / 抽样细节打包成 `build/diagnosis.md` |
| `dups` | **重复内容报告**:哪些 PDF 内容完全相同、实际要写多少章;`--write-pointers` 生成占位笔记 |
| `select` | **选课清单**:指定只对哪些课程做笔记;`--init` 生成模板,`--list` 预览命中 |
| `groups` | 按协议分组,生成**面试复习任务包**(`--list` 只看分组情况) |
| `build-group` | 校验 + 渲染**协议级面试复习笔记** |
| `write` | **调 LLM 自动撰写章节 note.json**(写→校验→回灌→重写闭环) |
| `write-group` | 调 LLM 自动撰写协议级 interview.json |
| `cost` | 汇总 AI 撰写的实际 token 用量与费用 |
| `stats` | **质量指标汇总**:密度/覆盖率/引用通过率等,用来客观对比不同模型 |

通用筛选参数(除 `init` / `doctor` / `index` 外都支持):

```bash
--id <pdf_id> [<pdf_id> ...]   # 支持 id 前缀
--path OSPF                    # 按相对路径关键字过滤
--limit 5                      # 只处理前 N 个
```

通用路径覆盖参数:`--config` `--source-root` `--notes-dir` `--build-dir`。
也可用环境变量 `NLNOTES_SOURCE_ROOT` / `NLNOTES_NOTES_DIR` / `NLNOTES_BUILD_DIR`。

## 阶段 1:`scan`

递归遍历 `source_root` 下所有 `*.pdf`(任意深度),跳过 `.git`、
`$RECYCLE.BIN`、`~$` 临时文件等。每个 PDF 得到一条记录:

```json
{
  "id": "ospf-neighbor-adjacency-69619352",
  "rel_path": "IGP/OSPF/OSPF Neighbor Adjacency.pdf",
  "title": "OSPF Neighbor Adjacency",
  "course_path": ["IGP", "OSPF"],
  "sha256": "…",
  "note_rel_path": "IGP/OSPF/ospf-neighbor-adjacency.md"
}
```

- `id` = 文件名 slug + 相对路径哈希,**稳定且唯一**,移动文件才会变。
- `note_rel_path` 保证输出目录树与源目录树完全镜像。
- 文件大小与修改时间都没变时复用旧哈希,几千个 PDF 也能秒级重扫。

## 阶段 2:`extract`

用 PyMuPDF **只读**打开 PDF,产出:

| 文件 | 内容 |
| --- | --- |
| `pages.json` | 每页纯文本、字符数、是否正文页、该页图片 id |
| `figures.json` | 图片清单:页码、尺寸、类型、图注推测、上方标题、周边上下文、OCR 文本 |
| `sections.json` | 标题层级(优先 PDF 书签,否则按字号推断) |
| `codeblocks.json` | 连续等宽字体行聚成的 CLI / 配置块 |
| `text.md` | 带 `[[p.N]]` 页标记的全文(交给 AI 读) |
| `figures/*.png` | 抽出的图片文件 |
| `extract.json` | 汇总元数据 + 源文件 SHA(用于增量跳过) |

### 图片抽取的两条路径

1. **位图**(NetworkLessons 的拓扑图多是 PNG):`page.get_images()` 取出原始字节,
   按尺寸/面积过滤图标与装饰,按像素哈希去重(同一张图在多页复用只留一次)。
2. **矢量图**:概念类课程(神经网络、SDN 架构、云架构)的图不是位图,而是
   **矩形 + 圆 + 箭头画出来的** —— `get_images()` 完全抽不到。工具会把邻近的绘图对象
   聚成簇,再按 2× 缩放渲染该区域为 PNG。三个关键细节:

   - **连接线不能丢**:箭头与连线的宽或高约等于 0,而它们恰恰是把框图各部分连起来的
     东西。丢了它们,一张图会被切成好几块(PyMuPDF 里宽高为 0 的矩形是 empty,
     `intersects()` 恒为 False,所以要先把退化的那一维撑开 1pt)。
   - **标签要一起框进来**:图里的文字(`Input 1`、`Neuron`、`0 or 1`、`* weight`)是
     独立文本对象,不在图形的 bbox 里。工具会迭代吸纳"距离近且很短"的文本行,
     长句子(正文段落)不会被吸进来(`vector_label_max_chars`)。
   - **边缘要收回来**:裁剪框如果蹭到一行正文,会把段落切一半进图里。
     工具会从正文段落处纵向收回裁剪框(收缩后高度不低于原来的 60%,否则宁可不收)。

   判断"这是一张图"而不是"标题下的一条分隔线",靠的是**成员数**
   (`vector_min_cluster_drawings`,默认 4)而不只是面积。

图注推测规则:先在图片下方 `caption_lookahead_pt`(默认 90pt)范围内找
以 `Figure` / `Fig.` / `Diagram` / `Topology` / `图` 开头的行;
找不到就取下方第一行;同时记录上方最近的短标题行和周边上下文。

> 图注是**推测**,只作为线索给 AI 判断,不会直接写进笔记。
> 笔记里的图注是 AI 写的 `caption_zh`,受门禁约束。

### 网页导出 PDF 的噪声清理

NetworkLessons 的 PDF 是从网页导出的,每页会夹带站点导航文字:
`Search …`、`Lessons`、`Lesson Contents` 及其侧边栏目录副本、翻页箭头 `«` `»`。

这些噪声有两个危害:一是污染原文证据库(AI 可能引用到导航文字),
二是**被字号推断误判成标题** —— 翻页箭头 `«` 字号很大,会被当成一级标题,
把真正的章节标题挤到二级。

抽取阶段会按整行匹配丢掉这些噪声,并在 `extract.json` 的 `noise_filter` 里
记录丢弃条数与去重样例,便于核对有没有误删正文。
清理在**三处同时生效**:`text.md`、grounding 证据库、标题识别 —— 口径保持一致。

```json
{
  "clean_text_noise": true,
  "text_noise_lines": ["search …", "lessons", "lesson contents", "home", "..."],
  "text_noise_patterns": ["^\\s*«", "»\\s*$", "^\\s*©\\s*\\d{4}"],
  "drop_toc_after_markers": ["lesson contents"],
  "drop_toc_max_lines": 25
}
```

只做**整行完全匹配**与少量正则,绝不做子串匹配 —— 否则会误删正文。
若发现误删,把对应词从 `text_noise_lines` 里去掉再 `extract --force`。

### 关键配置

```json
{
  "figure_min_width": 140, "figure_min_height": 90, "figure_min_area": 24000,
  "extract_vector_figures": true, "vector_min_drawings": 12,
  "figure_render_zoom": 2.0, "figure_dedupe": true,
  "caption_lookahead_pt": 90, "context_chars": 700,
  "figure_ocr": false, "ocr_lang": "eng"
}
```

抽到的图太多(把小图标也抽进来了)→ 调大 `figure_min_*`;
漏了图 → 调小,或确认是否需要开 `extract_vector_figures`。

## 阶段 2.5:重复内容识别(`dups`)

NetworkLessons 会把**同一节课交叉归档到多个认证方向**(CCNA / CCNP / CCIE /
Routing & Switching / Network Fundamentals),所以 PDF 文件数远大于实际课程数。
同一份内容写两遍中文笔记既浪费额度又没意义。

`scan` 阶段按 SHA-256 找出内容完全相同的文件,挑**路径排序最靠前的作为正本**,
其余标记 `dup_of`。后续所有阶段默认只处理正本(`skip_duplicate_content: true`)。

```bash
python -m nlnotes dups                    # 报告:实际要写多少章
python -m nlnotes dups --write-pointers   # 为副本生成指向正本的短笔记
```

`--write-pointers` 会在副本对应的镜像位置生成一篇很短的笔记,写明
"本节与某处内容完全相同,请看正本",并给出相对链接。这样 `notes/` 的目录树
仍与源课程目录**完整对应,不会出现空洞**,同时又只写了一份内容。

> 估算成本、工期时请用 `dups` 报出的**唯一课程数**,不要用文件总数。

## 阶段 3:`tasks`

为每个 PDF 生成自包含任务包:

```
build/tasks/<id>/
    TASK.md              总指令:硬约束 + 输出要求 + 阈值 + 常见失败处理
    source-text.md       原文全文(带 [[p.N]])
    outline.md           原文标题层级
    figures.md           图清单 + 每张图的原文上下文 + 预览相对路径
    glossary.md           本章命中的术语与统一译名
    codeblocks.md        原文 CLI / 配置块
    context.json         机器可读上下文(页数、图、阈值、输出路径)
    note.schema.json     输出结构(副本)
    note.template.json   骨架模板
    OUTPUT/note.json     ← AI 写这里
```

`TASK.md` 里的阈值是从当前配置**实时算出来的**,包括:
本章总页数、正文页数、可用图数、最少引用图数、覆盖度要求、题目数量区间、禁用词表。
所以 AI 不需要另外查配置。

术语表匹配用词边界匹配;短的全大写缩写(如 `AS`、`AD`、`TE`)要求大小写敏感,
避免命中 `address`、`state`、`such as` 这类普通英文。

## 阶段 4:AI 撰写 `note.json`

唯一需要模型的一步,也是唯一花钱的一步。
可以人工(Cursor 等会话)做,也可以用 `nlnotes write` 全自动跑
—— 详见 `docs/07-批量自动化与成本.md` 与 `docs/03-AI执行手册.md`。

`note.json` 的顶层结构:

```
pdf_id / source_rel_path / title_en / title_zh
summary_zh          本章概要(3~5 句)
scope_zh            本章边界声明(明确写出覆盖与不覆盖)
prerequisites_zh
sections[]          小节
  ├ heading_zh / heading_en / pages[]
  ├ points[]        知识点:text_zh + text_en_quote(逐字原文)+ page
  ├ figures[]       原文图引用:figure_id + caption_zh + explain_zh + labels_seen
  ├ visuals[]       自制图:kind + why_zh + grounding[] + spec
  ├ configs[]       配置块:code(逐字)+ explain_zh + annotations_zh
  └ tables[]
key_takeaways_zh[]
terms[]             en / zh / page
feynman
  ├ explain_back_zh 大白话复述(≥200 字,要有主线)
  ├ must_master[]   必须掌握:point_zh / why_zh / memory_hook_zh / evidence_quote
  ├ difficulties[]  难点:name_zh / why_hard_zh / how_to_break_zh / figure_refs / evidence_quote
  ├ questions[]     q_zh / q_en / answer_zh / answer_en / source_pages / evidence_quote
  ├ blind_spots_zh[]
  └ review_plan_zh[]
```

其中 `points[].detail_zh` 是"讲透"的关键字段:写机制怎么运作、成立的前提、
例外情况、与本章其他点的关系。跨页引用要在 `also_pages` 里登记。
知识点密度门禁(`X012`)会强制笔记有足够的条数,防止只写一层标题式概括。

完整定义见 `schemas/note.schema.json`(`additionalProperties: false`,不允许私自加字段)。

## 阶段 5:`verify`

9 组门禁,详见 `docs/04-验收与自测.md`。报告写到 `build/reports/<id>.json`:

```json
{
  "pdf_id": "…", "passed": true,
  "error_count": 0, "warning_count": 1,
  "stats": {
    "quotes_checked": 33, "quotes_matched": 33,
    "ungrounded_tokens": 0,
    "figures_available": 2, "figures_used": 2,
    "visuals": 3, "coverage_ratio": 1.0, "questions": 8
  },
  "errors": [], "warnings": [ … ]
}
```

每条错误都带 `code` / `where`(精确到 `sections[0].points[3]`)/ `message` / `fix`,
AI 可以直接照着改。

### 可调阈值

```json
{
  "quote_match_threshold": 90,       // 知识点引用相似度
  "visual_quote_threshold": 88,      // 自制图 grounding 相似度
  "coverage_min_ratio": 0.80,        // 正文覆盖率
  "min_questions": 8, "max_questions": 20,
  "required_question_types": ["concept", "process"],
  "min_figure_reference_ratio": 0.6,
  "token_grounding": true,
  "forbidden_phrases": [ … ],
  "token_whitelist": [ … ]
}
```

> **不要为了让 AI 过关而调低阈值。** 阈值调低等于放弃"不臆想"的保证。
> 唯一合理的调整是往 `token_whitelist` 里加与课程无关的通用词
> (如 `Markdown`、`OSI`),协议名/命令/数值一律不许加。

## 阶段 6:`visuals`(渲染)

| kind | 渲染结果 | 依赖 | 缺依赖时 |
| --- | --- | --- | --- |
| `packet_flow` | `<id>.gif`(动画)+ `<id>-steps.png`(分步静态图)+ `<id>.mp4` | 仅 Pillow | MP4 需要 ffmpeg,没有就只出 GIF + PNG |
| `mermaid` | `<id>.png` | mermaid-cli | 内联 mermaid 代码块 |
| `graphviz` | `<id>.png` | graphviz | 内联 dot 代码块 |
| `comparison_table` | Markdown 表格 | 无 | — |
| `ai_illustration` | `<id>.png`(带水印)+ `<id>-prompt.json` | API Key | 跳过生成,保留提示词并在笔记中说明 |

`packet_flow` 的画布高度按内容自适应(步骤说明行数、节点行数),
所以 2 个节点的简单流程不会留大片空白,5 个节点两行的拓扑也不会挤。

动画参数:

```json
{
  "anim_width": 1280, "anim_height": 420,   // height 是最小值,实际自适应
  "anim_frame_ms": 900,                     // 每个逻辑步骤的时长
  "anim_substeps": 6,                       // 每步插值出几帧(越大越顺滑、文件越大)
  "steps_grid_cols": 2                      // 分步静态图的列数
}
```

## 阶段 6.5:协议级面试复习笔记(`groups` / `write-group` / `build-group`)

章节笔记完成后,按目录聚合成协议级复习笔记。

**默认是自适应分组(`group_mode: "auto"`)。** 真实课程库的目录深度往往从 1 层到
6 层不等,固定层级要么把笔记切得太碎(某个叶子目录只有 2~3 章,撑不起三层追问),
要么并得太粗。自适应的做法是:先统计每个祖先目录下有多少章,再为每个 PDF
自底向上找**第一个章节数 ≥ `group_min_chapters`(默认 6)的祖先目录**。

举例:`Cisco/CCIE/Unit 1/1.2 Routing/1.2.f Route filtering/` 只有 3 章,
会自动上合并到 `Cisco/CCIE/Unit 1`(7 章),这样面试题素材才够。

```json
{ "group_mode": "auto", "group_min_chapters": 6, "group_chapters_budget_chars": 90000 }
```

跑之前先预览分组结果,确认粒度合适:

```bash
python -m nlnotes groups --list          # 人看
python -m nlnotes groups --list --json   # 机器读
```

**分组数 = 最终会产出多少份面试复习笔记。** 觉得切得太碎就调大
`group_min_chapters`,太粗就调小;想完全手工控制就把 `group_mode` 改成 `"depth"`,
再用 `group_depth` 指定层数(`<=0` 表示取最后一层目录)。

分组很大时(几十章),`chapters.md` 会按 `group_chapters_budget_chars` 均摊裁剪:
超预算的章节只保留小节标题,并注明完整内容在 `build/tasks/<pdf_id>/OUTPUT/note.json`。

```
build/groups/<group_id>/
    TASK.md                  面试复习任务指令(身份设定 + 六个区块要求 + 发散边界)
    chapters.md              本组各章的知识骨架(含 pdf_id 与页码,出题素材)
    context.json             机器可读上下文
    interview.schema.json    输出结构
    OUTPUT/interview.json    ← AI 写这里
```

**发散的处理方式**是这个阶段的核心设计:

| 内容 | 字段 | 校验 |
| --- | --- | --- |
| 核心答案、原理、机制、数值、判定顺序 | `answer_template_*` / `ideal_answer_*` / `layers[].answer_*` / `correct_*` | 严格:必须有 `grounding` 且逐条与原文比对 |
| 工程经验、厂商差异、版本演进 | `extension_zh` / `extension_en` | 不比对原文,但渲染为独立的「🔶 课程外扩展」区块 |

门禁(报告写到 `build/reports/group-<id>.json`):

- `A001`~`A004`:covered_chapters 必须属于本组、且该章已有笔记
- `A005`:`group_key` 必须与实际分组一致(笔记的输出路径只认分组自身的 key,不信任这个字段)
- `G001`~`G005`:每个条目至少 1 条 grounding;`pdf_id` 合法;页码合法;
  引用与原文比对(阈值 `interview_quote_threshold`,默认 88;页码错会告知正确页)
- `T001`:受约束字段里的技术词/数字必须在本组任意一章的原文中有依据
- `X001`/`X002`:中英双语纯度
- `X003`:各区块数量下限
- `X004`:连环追问必须正好三层且 level 依次为 1/2/3
- `F001`:不确定表述(据说 / 我猜 / 大概是)一律拦下

## 阶段 7:`assemble`

1. 把用到的原文图与渲染好的自制图复制到 `notes/<…>/assets/<pdf_id>/`;
2. 用 `templates/note.md.j2` 渲染 Markdown,图片用**相对路径**引用;
3. 写到 `notes/<与源目录相同的层级>/<课程>.md`;
4. 更新 `notes/README.md` 索引。

想改笔记排版(章节顺序、标题措辞、是否折叠答案),改模板即可,
不影响门禁与内容。模板用 Jinja2,`trim_blocks` 开启,
所以**内容行不要以 `{% %}` 结尾**,否则会吃掉换行导致 Markdown 表格/列表粘连。
