# 流水线详解

## 命令总览

| 命令 | 作用 |
| --- | --- |
| `init` | 生成 `config/pipeline.json` |
| `doctor` | 体检:路径 / 依赖 / 字体 / 可选工具 |
| `scan` | 扫描课程目录树 → `build/manifest.json` |
| `extract` | 抽原文、拓扑图、CLI 块 → `build/extract/<id>/` |
| `tasks` | 生成 AI 任务包 → `build/tasks/<id>/` |
| `prepare` | `scan` + `extract` + `tasks` 一条龙 |
| `next` | 列出接下来该写哪几章 |
| `verify` | 只跑门禁,输出报告 |
| `assemble` | 只组装 Markdown(跳过门禁) |
| `build` | `verify` + 渲染可视化 + `assemble`(**日常用这个**) |
| `index` | 重建 `notes/README.md` |
| `status` | 查看整体进度 |

通用筛选参数(除 `init` / `doctor` / `index` 外都支持):

```bash
--id <pdf_id> [<pdf_id> ...]   # 支持 id 前缀
--path OSPF                    # 按相对路径关键字过滤
--limit 5                      # 只处理前 N 个
```

通用路径覆盖参数:`--config` `--source-root` `--notes-dir` `--build-dir`。
也可用环境变量 `NLNOTES_SOURCE_ROOT` / `NLNOTES_NOTES_DIR` / `NLNOTES_BUILD_DIR`。

## 阶段 1:`scan`

递归遍历 `source_root` 下所有 `*.pdf`(任意深度),跳过 `.git`、
`$RECYCLE.BIN`、`~$` 临时文件等。每个 PDF 得到一条记录:

```json
{
  "id": "ospf-neighbor-adjacency-69619352",
  "rel_path": "IGP/OSPF/OSPF Neighbor Adjacency.pdf",
  "title": "OSPF Neighbor Adjacency",
  "course_path": ["IGP", "OSPF"],
  "sha256": "…",
  "note_rel_path": "IGP/OSPF/ospf-neighbor-adjacency.md"
}
```

- `id` = 文件名 slug + 相对路径哈希,**稳定且唯一**,移动文件才会变。
- `note_rel_path` 保证输出目录树与源目录树完全镜像。
- 文件大小与修改时间都没变时复用旧哈希,几千个 PDF 也能秒级重扫。

## 阶段 2:`extract`

用 PyMuPDF **只读**打开 PDF,产出:

| 文件 | 内容 |
| --- | --- |
| `pages.json` | 每页纯文本、字符数、是否正文页、该页图片 id |
| `figures.json` | 图片清单:页码、尺寸、类型、图注推测、上方标题、周边上下文、OCR 文本 |
| `sections.json` | 标题层级(优先 PDF 书签,否则按字号推断) |
| `codeblocks.json` | 连续等宽字体行聚成的 CLI / 配置块 |
| `text.md` | 带 `[[p.N]]` 页标记的全文(交给 AI 读) |
| `figures/*.png` | 抽出的图片文件 |
| `extract.json` | 汇总元数据 + 源文件 SHA(用于增量跳过) |

### 图片抽取的两条路径

1. **位图**(NetworkLessons 的拓扑图多是 PNG):`page.get_images()` 取出原始字节,
   按尺寸/面积过滤图标与装饰,按像素哈希去重(同一张图在多页复用只留一次)。
2. **矢量图**:某些 PDF 的拓扑图是矢量绘制。工具会统计一页的绘图对象数量,
   把邻近的绘制区域聚成簇,再按 2× 缩放渲染该区域为 PNG。

图注推测规则:先在图片下方 `caption_lookahead_pt`(默认 90pt)范围内找
以 `Figure` / `Fig.` / `Diagram` / `Topology` / `图` 开头的行;
找不到就取下方第一行;同时记录上方最近的短标题行和周边上下文。

> 图注是**推测**,只作为线索给 AI 判断,不会直接写进笔记。
> 笔记里的图注是 AI 写的 `caption_zh`,受门禁约束。

### 关键配置

```json
{
  "figure_min_width": 140, "figure_min_height": 90, "figure_min_area": 24000,
  "extract_vector_figures": true, "vector_min_drawings": 12,
  "figure_render_zoom": 2.0, "figure_dedupe": true,
  "caption_lookahead_pt": 90, "context_chars": 700,
  "figure_ocr": false, "ocr_lang": "eng"
}
```

抽到的图太多(把小图标也抽进来了)→ 调大 `figure_min_*`;
漏了图 → 调小,或确认是否需要开 `extract_vector_figures`。

## 阶段 3:`tasks`

为每个 PDF 生成自包含任务包:

```
build/tasks/<id>/
    TASK.md              总指令:硬约束 + 输出要求 + 阈值 + 常见失败处理
    source-text.md       原文全文(带 [[p.N]])
    outline.md           原文标题层级
    figures.md           图清单 + 每张图的原文上下文 + 预览相对路径
    glossary.md           本章命中的术语与统一译名
    codeblocks.md        原文 CLI / 配置块
    context.json         机器可读上下文(页数、图、阈值、输出路径)
    note.schema.json     输出结构(副本)
    note.template.json   骨架模板
    OUTPUT/note.json     ← AI 写这里
```

`TASK.md` 里的阈值是从当前配置**实时算出来的**,包括:
本章总页数、正文页数、可用图数、最少引用图数、覆盖度要求、题目数量区间、禁用词表。
所以 AI 不需要另外查配置。

术语表匹配用词边界匹配;短的全大写缩写(如 `AS`、`AD`、`TE`)要求大小写敏感,
避免命中 `address`、`state`、`such as` 这类普通英文。

## 阶段 4:AI 撰写 `note.json`

唯一需要 AI 的一步。详见 `docs/03-AI执行手册.md` 与 `prompts/`。

`note.json` 的顶层结构:

```
pdf_id / source_rel_path / title_en / title_zh
summary_zh          本章概要(3~5 句)
scope_zh            本章边界声明(明确写出覆盖与不覆盖)
prerequisites_zh
sections[]          小节
  ├ heading_zh / heading_en / pages[]
  ├ points[]        知识点:text_zh + text_en_quote(逐字原文)+ page
  ├ figures[]       原文图引用:figure_id + caption_zh + explain_zh + labels_seen
  ├ visuals[]       自制图:kind + why_zh + grounding[] + spec
  ├ configs[]       配置块:code(逐字)+ explain_zh + annotations_zh
  └ tables[]
key_takeaways_zh[]
terms[]             en / zh / page
feynman
  ├ explain_back_zh 大白话复述
  ├ questions[]     q_zh / q_en / answer_zh / answer_en / source_pages / evidence_quote
  ├ blind_spots_zh[]
  └ review_plan_zh[]
```

完整定义见 `schemas/note.schema.json`(`additionalProperties: false`,不允许私自加字段)。

## 阶段 5:`verify`

9 组门禁,详见 `docs/04-验收与自测.md`。报告写到 `build/reports/<id>.json`:

```json
{
  "pdf_id": "…", "passed": true,
  "error_count": 0, "warning_count": 1,
  "stats": {
    "quotes_checked": 33, "quotes_matched": 33,
    "ungrounded_tokens": 0,
    "figures_available": 2, "figures_used": 2,
    "visuals": 3, "coverage_ratio": 1.0, "questions": 8
  },
  "errors": [], "warnings": [ … ]
}
```

每条错误都带 `code` / `where`(精确到 `sections[0].points[3]`)/ `message` / `fix`,
AI 可以直接照着改。

### 可调阈值

```json
{
  "quote_match_threshold": 90,       // 知识点引用相似度
  "visual_quote_threshold": 88,      // 自制图 grounding 相似度
  "coverage_min_ratio": 0.80,        // 正文覆盖率
  "min_questions": 8, "max_questions": 20,
  "required_question_types": ["concept", "process"],
  "min_figure_reference_ratio": 0.6,
  "token_grounding": true,
  "forbidden_phrases": [ … ],
  "token_whitelist": [ … ]
}
```

> **不要为了让 AI 过关而调低阈值。** 阈值调低等于放弃"不臆想"的保证。
> 唯一合理的调整是往 `token_whitelist` 里加与课程无关的通用词
> (如 `Markdown`、`OSI`),协议名/命令/数值一律不许加。

## 阶段 6:`visuals`(渲染)

| kind | 渲染结果 | 依赖 | 缺依赖时 |
| --- | --- | --- | --- |
| `packet_flow` | `<id>.gif`(动画)+ `<id>-steps.png`(分步静态图)+ `<id>.mp4` | 仅 Pillow | MP4 需要 ffmpeg,没有就只出 GIF + PNG |
| `mermaid` | `<id>.png` | mermaid-cli | 内联 mermaid 代码块 |
| `graphviz` | `<id>.png` | graphviz | 内联 dot 代码块 |
| `comparison_table` | Markdown 表格 | 无 | — |
| `ai_illustration` | `<id>.png`(带水印)+ `<id>-prompt.json` | API Key | 跳过生成,保留提示词并在笔记中说明 |

`packet_flow` 的画布高度按内容自适应(步骤说明行数、节点行数),
所以 2 个节点的简单流程不会留大片空白,5 个节点两行的拓扑也不会挤。

动画参数:

```json
{
  "anim_width": 1280, "anim_height": 420,   // height 是最小值,实际自适应
  "anim_frame_ms": 900,                     // 每个逻辑步骤的时长
  "anim_substeps": 6,                       // 每步插值出几帧(越大越顺滑、文件越大)
  "steps_grid_cols": 2                      // 分步静态图的列数
}
```

## 阶段 7:`assemble`

1. 把用到的原文图与渲染好的自制图复制到 `notes/<…>/assets/<pdf_id>/`;
2. 用 `templates/note.md.j2` 渲染 Markdown,图片用**相对路径**引用;
3. 写到 `notes/<与源目录相同的层级>/<课程>.md`;
4. 更新 `notes/README.md` 索引。

想改笔记排版(章节顺序、标题措辞、是否折叠答案),改模板即可,
不影响门禁与内容。模板用 Jinja2,`trim_blocks` 开启,
所以**内容行不要以 `{% %}` 结尾**,否则会吃掉换行导致 Markdown 表格/列表粘连。
