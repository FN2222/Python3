# 常见问题

## 路径与扫描

**Q:`课程根目录不存在`,但路径明明是对的。**

JSON 里单反斜杠是转义符。写成正斜杠或双反斜杠:

```json
{ "source_root": "D:/NetworkLessons/All-Courses-v3.0" }
```

命令行传参不受影响:`--source-root "D:\NetworkLessons\All-Courses-v3.0"`。

**Q:扫描到 0 个 PDF。**

确认扩展名是 `.pdf`(大小写不敏感,工具已处理),且文件不在被跳过的目录里
(`.git`、`node_modules`、`$RECYCLE.BIN`、`System Volume Information`),
文件名不以 `~$` 或 `.` 开头。

**Q:课程目录层级很深(方向/子方向/协议/主题/…),支持吗?**

支持任意深度。输出目录树与源目录树**完全镜像**,不会压平。

**Q:重命名或移动了 PDF,`pdf_id` 变了怎么办?**

`pdf_id` 含相对路径哈希,移动后会变成新 id,旧的抽取产物与任务包会残留。
重跑 `scan` 后用 `status` 看到"未开始"的新 id,重新走一遍即可;
旧产物可手动删除 `build/extract/<旧id>` 与 `build/tasks/<旧id>`。

## 配置文件

**Q:文档里说的某个配置项,我在 `config\pipeline.json` 里找不到。**

因为 `pipeline.json` 是你**第一次 `init` 时生成的快照**,后续版本新增的配置项不会
自动出现在里面。程序会用内置默认值兜底(所以功能正常),但你看不到、也没法改。

补齐:

```powershell
python -m nlnotes init --upgrade
```

它会**保留你改过的所有值**,只补上缺少的新增项、清掉已废弃的项,
并把原文件备份成 `pipeline.json.bak`。`nlnotes init` 和 `nlnotes doctor`
都会主动告诉你配置是不是旧版。

想看每一项的含义与默认值,对照 `config/pipeline.example.json`
(它跟着代码一起更新,永远是最新的)与 `docs/02-流水线详解.md`。

**Q:`git pull` 一直报证书错误,每次更新都要手工下 ZIP,太麻烦。**

用一键更新脚本,它不依赖 git:

```powershell
cd D:\Python3
.\scripts\Update.ps1 -UpgradeConfig -ReExtract
```

它做四件事:下载分支 ZIP → 覆盖代码 → 补齐配置项 → (可选)重跑抽取。
下载走的是 PowerShell 的 `Invoke-WebRequest`,用 **Windows 证书存储**校验 ——
浏览器能访问 GitHub,它一般就能成功(而 git 的 schannel 可能因为吊销检查
失败而报 `SEC_E_UNTRUSTED_ROOT`)。

脚本明确跳过你的东西:`config\pipeline.json`、`config\selection.txt`、
`build\`、`notes\`、`.venv\`。

如果你想彻底修好 git,先试这一行(只关吊销检查,不降低证书校验强度):

```powershell
git config --global http.schannelCheckRevoke false
```

**Q:报"配置文件里有当前版本不认识的字段"。**

说明你的配置里有已经改名或删除的旧项。这只是警告,不影响运行(那些字段会被忽略)。
跑 `python -m nlnotes init --upgrade` 清理即可。

## Windows 长路径

**Q:报 `[WinError 3] 系统找不到指定的路径`,但那个文件明明存在。**

Windows 默认有 **260 字符的完整路径上限**(MAX_PATH)。真实课程库的目录很深,
例如:

```
D:\NetworkLessons\All-Courses-v3.0\Cisco\CCIE Enterprise Infrastructure\
Unit 4 Infrastructure Security and Services\4.2 Network Security\
4.2.c IPv6 Infrastructure Security Features\IPv6 First Hop Security (FHS) Features\
249 - IPv6 First Hop Security (FHS) Features.pdf
```

这条路径 268 字符,超了 8 个字符,于是打不开。

工具**内部已经用长路径模式处理**(给路径加 `\\?\` 前缀),读源 PDF、写图片、
写笔记都走这条路,所以一般不需要你做什么;`nlnotes doctor` 也会告诉你有多少个超长路径。

但**强烈建议同时打开系统的长路径支持**,这样其他工具(资源管理器、编辑器、
Git)也不会出问题。以管理员身份运行 PowerShell:

```powershell
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
  -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
```

改完**重启一次**。也可以用 `gpedit.msc` → 计算机配置 → 管理模板 → 系统 →
文件系统 → 启用 Win32 长路径。

**Q:输出的笔记路径也会超长吗?**

会。`notes\` 镜像了源目录树,再加上 `assets\<pdf_id>\fig-p001-1.png`,
最深的能到 270 多字符。同样由长路径模式处理。
如果你想彻底避开,把仓库放在更短的路径下(例如 `D:\nl` 而不是
`D:\Users\xxx\Documents\Projects\Python3`),能省出十几个字符。

## 抽取

**Q:一张图都没抽到。**

三种可能:

1. PDF 是**扫描件**(整页是一张大图),此时文本层也是空的。
   `extract.json` 里 `pages_total` 有值但每页 `char_count` 接近 0 就是这种情况。
   这类 PDF 需要先做 OCR 转成可搜索 PDF,本流水线不处理扫描件。
2. 拓扑图是矢量绘制且绘图对象数量低于 `vector_min_drawings`(默认 12)。
   把它调小(如 6)再 `extract --force`。
3. 图片尺寸小于过滤阈值。调小 `figure_min_width` / `figure_min_height` / `figure_min_area`。

**Q:抽到一堆图标、logo、装饰条。**

调大 `figure_min_area`(如 40000)与 `figure_min_width`(如 200),再 `extract --force`。
也可以抽完人工删掉 `build/extract/<id>/figures/` 里不要的文件,
但要同时从 `figures.json` 里删对应条目,否则 AI 还会看到它。

**Q:同一张图被抽了好几次。**

`figure_dedupe` 默认开启,按像素哈希去重。若是"内容相同但尺寸不同"的两份,
哈希不同所以不会去重 —— AI 会看到两个 id,选一个引用即可。

**Q:矢量图被切成好几块。**

调大 `_cluster_rects` 的合并间距不方便时,更简单的办法是调大
`vector_min_cluster_area`,过滤掉碎片,只留主图区域。

## 自制图与动画

**Q:动画/静态图里的中文变成方块。**

没找到中文字体。在配置里显式指定:

```json
{ "font_path": "C:/Windows/Fonts/msyh.ttc" }
```

Linux 装 `fonts-noto-cjk` 或 `fonts-wqy-microhei`。用 `doctor` 确认。

**Q:GIF 太大。**

调小 `anim_substeps`(6 → 3)或 `anim_width`(1280 → 1000)。
分步静态图 PNG 通常比 GIF 小得多,只想要静态图的话可以在模板里
把 `r.animation` 那段去掉。

**Q:没装 mermaid-cli,笔记里出现的是代码块,能看吗?**

能。Obsidian、Typora、VS Code(带 Markdown Preview Mermaid 插件)、GitHub
都会把 ```mermaid 代码块渲染成图。想要静态 PNG 就装 mermaid-cli。

**Q:MP4 没生成。**

需要 ffmpeg。没有也不影响 —— GIF 与分步静态图已经足够。

**Q:AI 示意图没生成,也没报错。**

设计如此:未配置 `illustration_provider` 或未设置 API Key 时,
工具会跳过生成、保留提示词(存在 `build/visuals/<id>/<vid>-prompt.json`),
并在笔记里给出说明,不会中断流水线。

**Q:Gemini 报模型不存在。**

图像模型名会随厂商更新。改 `config/pipeline.json` 的 `gemini_model` 即可,
代码无需修改。

## 门禁

**Q:`Q001` 大面积失败。**

几乎都是 AI "凭记忆写英文"而不是复制粘贴。让它重新从 `source-text.md` 复制。
另一种情况是 PDF 有连字符断行(`neigh-\nbor`),导致原文文本层里的词被拆开;
这种情况下让 AI 换一句更完整的句子作为引用。

**Q:`T001` 报出的是拓扑图里的设备名 / 网段。**

正确做法是在引用那张图的 `figures[].labels_seen` 里登记这些标签。
详见 `docs/00-总体方案.md` 的"关于拓扑图里的文字"。

**Q:`T001` 报出的是通用词(如 `Markdown`、`OSI`)。**

可以加进 `token_whitelist`。但**协议名、命令、数值一律不许加白名单** ——
那样等于关掉了反臆想。

**Q:`X001` 覆盖度总是过不了。**

对照 `build/tasks/<id>/context.json` 的 `content_pages`,
和自己写的 `sections[].pages` 做差集,看漏了哪几页,针对性补内容。
若某几页确实是版权页/目录页(被误判成正文),可以把
`coverage_min_ratio` 从 0.80 略微下调到 0.70,但不要更低。

**Q:章节很短(1~2 页),小节数警告怎么办?**

`X009` 是**警告**,不影响通过。短章节小节少是正常的。

**Q:能不能让门禁宽松点,先把量做出来?**

不建议。这套方案的价值就在"笔记可信"。真要临时出草稿,用
`python -m nlnotes build --id <id> --force`,它会生成 Markdown 但在
front matter 里标 `verified: false`,便于事后区分。

## 产物与阅读

**Q:笔记里的图片显示不出来。**

图片用相对路径 `assets/<pdf_id>/xxx.png`。确认你是**在 `notes/` 目录结构里**
打开 Markdown(比如把 `notes/` 作为 Obsidian 库根目录),
不要把单个 `.md` 文件复制到别处。

**Q:想把 `notes/` 提交进 Git。**

删掉 `.gitignore` 里的 `notes/` 一行。注意 GIF/PNG 会让仓库变大,
量大时考虑 Git LFS。

**Q:想改笔记的排版/章节顺序。**

改 `templates/note.md.j2`。注意模板开了 `trim_blocks`,
**内容行不要以 `{% ... %}` 结尾**,否则会吃掉换行,导致表格和列表粘连。
改完用 `python -m nlnotes assemble --id <id>` 快速预览效果。

**Q:我想一次做一个协议(这次 OSPF,下次 BGP),怎么配?**

这是推荐的推进方式。两处配置:

1. `config/selection.txt` 一条规则对应一个协议:

```
Routing & Switching/OSPF
```

2. `config/pipeline.json` 把分组模式设为 `selection`:

```json
{ "group_mode": "selection" }
```

这样**一条选课规则 = 一份面试复习笔记**,正好实现"整个 OSPF 的章节笔记后面
跟一份 OSPF 面试复习笔记"。

每一轮的完整流程:

```powershell
#  改 selection.txt 只留这一个协议
python -m nlnotes select --list          # 确认命中数
python -m nlnotes extract --force        # 只抽这一批
python -m nlnotes tasks --force
python -m nlnotes next --count 3         # 交给 AI 逐批写
#  ...(章节全部写完)
python -m nlnotes build                  # 出章节笔记
python -m nlnotes groups                 # 建面试复习任务包
#  ...(AI 写 interview.json)
python -m nlnotes build-group            # 出面试复习笔记
python -m nlnotes stats --detail         # 看这一轮的质量
#  换下一个协议,重复
```

**为什么按协议而不是一次全铺开**:面试复习笔记要等该协议的章节全部写完才能做。
按协议推进,每一轮结束你都拿到一个完整可用的成果(章节笔记 + 面试笔记),
而不是几百个半成品。

**Q:课程太多,我只想做其中一部分。**

用**选课清单**,不用每条命令都写 `--path`:

```powershell
python -m nlnotes select --init     # 按你的课程库生成模板(带各方向章节数)
#   编辑 config/selection.txt,取消你要做的方向前面的 #
python -m nlnotes select --list     # 预览命中了哪些
```

清单一旦生效,`extract` / `tasks` / `write` / `build` / `groups` 全部自动遵守。
写法:

```
Routing & Switching/OSPF      # 目录名片段,包含即匹配
Cisco/CCNP ENCOR*/Unit 2*     # 含 * 或 ? 时按通配符匹配整条相对路径
!*/Labs/*                     # ! 开头表示排除,排除优先于包含
```

**Q:我只选了两个目录,为什么命中的数量对不上?**

不含通配符的规则按**路径前缀**匹配,不是任意子串。所以:

- `Cisco/ASA Firewall` → 只命中 `Cisco/ASA Firewall/...`
- `Troubleshooting` → 只命中**顶层**的 `Troubleshooting/...`,
  **不会**误命中 `Cisco/CCNP ENARSI 300-410 v1.1/Unit 6 Troubleshooting/...`

想匹配任意层级,必须显式写通配符:`*Troubleshooting*` 或 `*/OSPF/*`。

数量对不上时,跑 `select --list` 看**每条规则各自命中多少** ——
一眼就能看出是哪条规则超出预期,或者哪条规则写错了(命中 0 个会有告警)。

还有一个常见原因:模板里的 `===== Cisco(992 章)=====` 是分隔装饰行。
取消注释时如果把整块的 `#` 都删了,分隔行也会跟着变成"规则"。
程序会忽略这类装饰行,但**你可能连带取消了不想选的课程行** —— 对照 `select --list` 确认。

**Q:我已经装了 tesseract,为什么还报 `G011:未开 OCR`?**

按顺序查这三件事,九成是第 1 或第 3 条:

1. **`config\pipeline.json` 里 `figure_ocr` 是不是 `true`?** 装了软件不等于开了开关。
2. **`nlnotes doctor` 里「图内文字 OCR」显示什么?**
   - `✅ 可用 — C:\Program Files\Tesseract-OCR\tesseract.exe` → 正常
   - `❌ 已开启但不可用` → 按它给的原因处理。最常见的是
     **UB-Mannheim 安装包默认不把 tesseract 加进 PATH**。
     工具会自动探测常见安装位置;探测不到就在 config 里写完整路径:
     ```json
     { "tesseract_cmd": "C:/Program Files/Tesseract-OCR/tesseract.exe" }
     ```
3. **改完有没有重跑 `extract --force`?**
   OCR 文本是存在**抽取产物**里的,不重新抽取不会生效:
   ```powershell
   python -m nlnotes extract --force
   python -m nlnotes tasks --force
   ```

**Q:OCR 显示可用了,还需要重跑抽取吗?**

**需要。** `doctor` 显示 ✅ 只代表"现在能做 OCR",而 OCR 文本是存在
**抽取产物**(`build/extract/<id>/figures.json` 的 `ocr_text` 字段)里的。
之前抽取时 OCR 不可用,那些产物里这个字段是空的,所以门禁仍然认为"没有 OCR"。

```powershell
python -m nlnotes extract --force
python -m nlnotes tasks --force
```

`tasks --force` 只重写任务包的**输入**文件(原文、图清单、术语表),
**不会动 `OUTPUT/note.json`** —— 已经写好的笔记不会丢。

一个提醒:**开了 OCR,抽取会明显变慢**(每张图都要跑一次识别)。
所以建议**先把选课清单收窄到这一轮要做的协议,再重跑抽取**,
别对着 877 章跑一遍 OCR。大批量时命令会打印进度与预计剩余时间。

**Q:OCR 认错字怎么办?会不会把正确的标签判成错误?**

不会阻塞你。OCR 对图里的小字号很不可靠 —— 实测会把 `192.168.12.0/24` 认成
`192,188, 12.0/24`,更小的 `R1`、`R2` 甚至整个识别不出来。

所以设计上做了两件事:

- **"标签在 OCR 里找不到"默认只是警告**,不是错误 —— 否则正确的标签会被误判、
  把 AI 卡死。想升级成硬错误,把 `ocr_label_mismatch_as_error` 设为 `true`。
- **比对前会抹平标点差异**(逗号→句点、去空格),再做模糊匹配。

反过来,OCR 成功认出的文字会**直接纳入证据词表**(`ocr_text_as_evidence`),
所以子网划分、VLAN 这类图上带一二十个网段的章节,AI 不必逐个手工登记也能引用。

**Q:抽出来的"图"其实是页面装饰或整页正文。**

网页导出的 PDF 里有三类东西很像图,已经在过滤:

- **页面装饰** —— 搜索框、深色模式按钮、侧边栏 `Lesson Contents` 目录框。
  它们都有边框矩形,纵向排列时会连成一大片。判据是"该区域里有被噪声过滤丢掉的导航文字"。
- **整页正文** —— 内容外框 + 项目符号会聚成接近整页的一块。
  判据是长文本行数(`vector_max_long_text_lines`)与占页比例(`vector_max_page_ratio`)。
- **分隔线 / 表格边框** —— 判据是"面积越大,要求的图形对象越多"
  (`vector_area_per_extra_drawing`)。

如果还有漏网的,把 `vector_max_page_ratio` 调小(如 0.45)或
`vector_max_long_text_lines` 调小(如 2),然后 `extract --force`。
反过来,如果**真图被过滤掉了**,把这两项调大。

**Q:怎么客观比较不同模型写出来的笔记质量?**

```powershell
python -m nlnotes stats --detail
```

它汇总所有已校验章节的客观指标:知识点密度、每章知识点数、覆盖率、
引用校验通过率、拓扑图引用数、自制图数量、费曼题目数、无原文依据的 token 数。

用法:先用模型 A 跑 3 章看一遍数,再用模型 B 跑 3 章对比。
**密度 / 覆盖率 / 自制图数量越高说明笔记越扎实;未通过数与无依据 token 越高
说明模型越吃力**(意味着更多重试、更耗额度)。

**Q:同一节课出现在多个认证方向下,会重复做吗?**

不会重复做字节完全相同的。`scan` 会按 SHA-256 找出完全相同的文件,
只给"正本"写笔记,副本用一篇指向正本的短笔记占位
(`nlnotes dups --write-pointers`),目录树不留空洞。

但交叉归档时文件常被**重新导出**,字节不同而内容相同 —— 这类字节哈希抓不到。
所以 `nlnotes dups` 还会按**标题**(去掉序号前缀)找近似重复,默认**只报告不跳过**。
确认确实重复后,把 config 的 `skip_title_duplicates` 设为 `true` 即可跳过。

**Q:术语译名不统一。**

补 `glossary/terms.csv`(格式 `en,zh,category,aliases`),
重跑 `tasks` 让新术语进入任务包。已写好的章节会在 `T003` 警告里提示不一致。

## 性能

**Q:几千个 PDF,准备阶段要多久?**

主要开销在 `extract`(解析 PDF + 写图片)。单个 PDF 通常在百毫秒到数秒之间,
取决于页数与图片数量。可以分批:

```bash
python -m nlnotes prepare --path Switching
python -m nlnotes prepare --path IGP
```

重跑时未改动的 PDF 会被 SHA-256 缓存跳过。

**Q:能并行吗?**

`extract` 目前是串行的。要加速可以按一级目录开多个进程,
分别指定不同的 `--path`(它们写入不同的 `build/extract/<id>` 子目录,互不冲突)。
注意 `scan` 与 `manifest.json` 不要并发写。
