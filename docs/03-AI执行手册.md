# AI 执行手册

> 面向"让 AI 工具自动把上千个 PDF 做成笔记"的落地操作。
> 人类只需要跑准备阶段和抽检,中间的撰写—校验—修订闭环由 AI 自己完成。
>
> **如果你只想全自动跑完、不想逐章下发指令**,直接看
> [`docs/07-批量自动化与成本.md`](07-批量自动化与成本.md) 的 `nlnotes write`
> —— 本文档适用于"用 Cursor 之类的会话逐章做"或"自建脚本"的场景。

## 一、单章标准流程(AI 视角)

```
1. Read  build/tasks/<id>/TASK.md
2. Read  build/tasks/<id>/source-text.md          (全文,记住 [[p.N]])
3. Read  build/tasks/<id>/outline.md
4. Read  build/tasks/<id>/figures.md
   └ 对每个 figure,打开预览路径的 PNG **实际看图**,记下图上的文字标签
5. Read  build/tasks/<id>/glossary.md, codeblocks.md
6. Write build/tasks/<id>/OUTPUT/note.json
7. Run   python -m nlnotes build --id <id>
8. 若失败:Read build/reports/<id>.json,按 errors 逐条改 note.json,回到 7
   (最多 5 轮;5 轮不过则停下并汇报剩余错误)
```

必须遵守的写法规则在:

- `prompts/00-system-中文笔记作者.md` —— 铁律与翻译规范(设为 system prompt)
- `prompts/20-可视化设计.md` —— 什么时候自制图、规格怎么写
- `prompts/30-费曼测验.md` —— 出题规范与双语要求
- `prompts/40-修订循环.md` —— 错误码 → 改法对照表

## 二、在各类工具里怎么接

### Cursor / Claude Code / 任意有文件读写与终端能力的 Agent

把 `prompts/00-system-中文笔记作者.md` 放进项目规则(Cursor 可用 `.cursor/rules`),
然后每章发一条消息:

```
读 build/tasks/<id>/TASK.md 并严格按它的要求产出 build/tasks/<id>/OUTPUT/note.json。
figures.md 里的每张图都要打开看,把图上的文字登记到 labels_seen。
写完运行 python -m nlnotes build --id <id>,按 build/reports/<id>.json 的报告
逐条修到通过为止。不要修改门禁配置。
```

批量推进时,先取任务列表:

```bash
python -m nlnotes next --count 10
```

然后逐个下发。**一次只做一章**,不要让 AI 同时开多章 —— 上下文混起来最容易串页码。

### 只有对话、没有文件权限的 AI(网页版)

1. 人工把 `TASK.md` + `source-text.md` + `figures.md` + `glossary.md` 粘贴进去
   (若原文太长,按 `chunk_chars` 分批粘,并强调"先读完再动手");
2. 图片需要单独上传给它看(多模态),否则它无法填 `labels_seen`
   —— 也可以开启 `figure_ocr`,让 OCR 结果出现在 `figures.md` 里,
   这样纯文本模型也能拿到图上的标签;
3. 让它输出完整 `note.json`,人工保存到 `OUTPUT/note.json`;
4. 人工运行 `python -m nlnotes build --id <id>`,把报告贴回去让它改。

### 自建脚本调 API

任务包已经是"喂给模型的现成上下文"。伪代码:

```python
import json, subprocess
from pathlib import Path

task = Path("build/tasks") / pdf_id
system = Path("prompts/00-system-中文笔记作者.md").read_text(encoding="utf-8")
context = "\n\n".join(
    f"===== {name} =====\n" + (task / name).read_text(encoding="utf-8")
    for name in ["TASK.md", "source-text.md", "outline.md",
                 "figures.md", "glossary.md", "codeblocks.md"])
schema = (task / "note.schema.json").read_text(encoding="utf-8")

for attempt in range(5):
    note_json = call_llm(system=system, user=context + "\n\n" + schema + extra_feedback)
    (task / "OUTPUT" / "note.json").write_text(note_json, encoding="utf-8")
    rc = subprocess.run(["python", "-m", "nlnotes", "build", "--id", pdf_id]).returncode
    if rc == 0:
        break
    report = json.loads(Path(f"build/reports/{pdf_id}.json").read_text(encoding="utf-8"))
    extra_feedback = ("\n上一轮未通过,请逐条修正后重新输出完整 note.json:\n"
                      + json.dumps(report["errors"], ensure_ascii=False, indent=2))
```

要点:

- 让模型输出**完整的** `note.json`,不要输出 diff / 片段,避免拼接出错;
- 把 `errors` 原样回灌,里面已经含 `where` 定位和 `fix` 建议;
- 有多模态能力时,把 `build/extract/<id>/figures/*.png` 一起传进去,
  `labels_seen` 的质量会明显更好。

## 三、AI 最容易犯的 6 个错(以及怎么避免)

| 错误 | 表现 | 预防 |
| --- | --- | --- |
| **凭记忆写原文** | `Q001` 大面积失败 | 强调 `text_en_quote` 必须是**复制粘贴**,不是"根据理解写出" |
| **默认值张口就来** | `T001` 报出没出现过的数字 | 只写原文明确给出的数值;原文没说默认值就不提默认值 |
| **描述拓扑图时编设备名** | `T001` 报出 `R3`、`Gi0/2` | 先看图,先填 `labels_seen`,再写讲解 |
| **补充"实战经验"** | `F001` 禁用词 | 反复强调"本章没讲的即使你知道也不写" |
| **只做前几页** | `X001` 覆盖度不足 | 写之前先按 `content_pages` 列一遍小节大纲 |
| **只写一层标题式概括** | `X012` 知识点密度过低 | 每个正文页至少 2 条知识点;机制性的点补 `detail_zh` |
| **超纲出题** | `X011` | 出题前先确认答案在正文小节里已经写过 |
| **把工程经验写进面试题答案** | `T001` / `G005` | 移到 `extension_zh` / `extension_en` |

## 三点五、协议级面试复习笔记的流程

某个协议下的章节笔记都完成之后,再做这一份。AI 视角的流程:

```
1. Run   python -m nlnotes groups --list        (确认该协议已完成几章)
2. Run   python -m nlnotes groups --group OSPF  (生成任务包)
3. Read  build/groups/<group_id>/TASK.md
4. Read  build/groups/<group_id>/chapters.md    (出题素材,含 pdf_id 与页码)
5. Read  build/extract/<pdf_id>/text.md         (需要逐字复制英文原句时)
6. Write build/groups/<group_id>/OUTPUT/interview.json
7. Run   python -m nlnotes build-group --group OSPF
8. 若失败:读 build/reports/group-<group_id>.json,逐条修,回到 7
```

系统提示词用 [`prompts/50-面试复习.md`](../prompts/50-面试复习.md)(**不要**用章节笔记那份,
两者规则不同:章节笔记零发散,面试笔记允许发散但必须分栏)。

这一步 AI 最容易犯的错是**把工程经验写进核心答案**。判断标准很简单:
这句话能不能在本协议的课程 PDF 里找到依据?能就放核心答案并给 `grounding`,
不能就放 `extension_zh` / `extension_en`。放错会被 `T001` 或 `G005` 拦下。

## 四、批量调度建议

0. **先体检**:`python -m nlnotes audit`,把扫描件之类不可用的 PDF 先剔除掉,
   否则会在这些文件上白跑一遍(它们抽不到原文,必然过不了门禁)。
1. **先小批验证**:`python -m nlnotes prepare --path <某协议> --limit 3`,
   人工通读这 3 篇笔记,确认风格与深度符合预期,再放开规模。
2. **按方向分批**:一次一个一级目录(Switching / IGP / BGP / …),
   每批做完看 `notes/README.md` 的状态统计。
3. **失败隔离**:`build` 会跳过未通过的章节并继续下一个,最后汇总失败 id。
   把这些 id 单独拎出来重试或人工处理。
4. **进度可视**:
   ```bash
   python -m nlnotes status --detail
   ```
5. **增量安全**:PDF 用 SHA-256 缓存,重跑 `extract` 不会重复劳动;
   `note.json` 已存在的章节不会被 `tasks` 覆盖(只有 `--force` 会重置模板文件)。

## 五、人工抽检要点

门禁能保证"没有编造",但保证不了"讲得好"。建议每 10~20 篇抽检 1 篇,看四件事:

1. **中文读起来顺不顺** —— 有没有翻译腔长句;
2. **图放对了没有** —— 拓扑图是不是配在对应的知识点旁边;
3. **自制图有没有必要** —— `why_zh` 是否真的指出了一个抽象点,
   而不是为了凑图而画;
4. **费曼题目值不值得答** —— 是不是"照抄一句原文就能答"的水题,
   有没有覆盖本章真正的重点。

发现风格问题,改 `prompts/`(写法)或 `templates/note.md.j2`(排版),
**不要改门禁阈值**。
