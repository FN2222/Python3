# 完整制作方案:把 `D:\NetworkLessons\All-Courses-v3.0` 做成中文笔记

> 本文是**可直接执行的方案**。照着"第 4 章 执行步骤"从上到下敲命令,
> 中间只有一步需要 AI 参与(写 `note.json`),其余全部自动化。

---

## 1. 需求 → 方案对照

| 你的要求 | 方案怎么做到 |
| --- | --- |
| 遍历任意深度嵌套的课程文件夹 | `nlnotes scan` 递归扫描,输出目录树与源目录**一一镜像** |
| 把 PDF 内容做成中文笔记 | AI 产出结构化 `note.json`,工具渲染成 Markdown |
| **笔记详尽扎实,杜绝空洞概括** | `points[].detail_zh` 深入说明(机制/前提/例外);**知识点密度门禁 `X012`**(默认 ≥2.0 条/正文页);摘要、要点、答案均设长度下限 |
| 知识点附上文章中的拓扑图 | `nlnotes extract` 从 PDF 抽出位图/矢量拓扑图,笔记按 `figure_id` 引用,门禁强制引用比例 |
| 难懂/抽象处用工具自制动画静态图 | `packet_flow` 用纯 Pillow 自绘 **动画 GIF + 分步静态图 PNG + MP4**;还支持 mermaid / graphviz / 对比表;抽象类比可选调用 Gemini(nano banana 系列)或 OpenAI 图像模型 |
| 严格按 PDF 英文内容,不发散不臆想 | 每条知识点必须附**逐字原文英文句**并通过模糊比对;中文里的每个英文词与数字都要回查原文;禁用发散措辞;9 组门禁不通过就不出笔记 |
| **章末费曼:巩固 + 必须掌握 + 难点** | 章节笔记的费曼部分固定六步:大白话复述 → **必须掌握清单**(含为什么必须掌握 + 记忆抓手)→ **难点分析**(难在哪 / 为什么难 / 怎么突破)→ 自测题 → 盲点 → 复习计划。全部严格限定本章原文 |
| **面试相关放在整个协议之后** | 新增**协议级面试复习笔记**:按目录聚合(整个 OSPF / 整个 BGP),含高频必考原理题(高分答题模板 + 得分要点)、场景化面试题(情景模拟 + 解题框架)、**三层递进连环追问**、避坑指南 |
| **面试部分可以发散** | 允许,但**分栏放置**:核心答案必须有 `grounding` 原文依据并逐条比对;工程经验只能放 `extension_*` 字段,渲染为「🔶 课程外扩展」独立区块 |
| 题目与答案中英双语 | 章节题目与面试题目均强制中英双份字段,并校验语言纯度(中文字段必须含中文、英文字段不得含中文) |
| 费曼题目不超纲 | 每题必须有 `evidence_quote`,且引用页必须是正文已覆盖的页(`X011`) |
| **PDF 是否合格、有问题的踢出来** | `nlnotes audit` 逐个体检:可搜索性、是否扫描件、是否加密、文字是否乱码;三档分级并**自动剔除**不可用文件,后续阶段跳过 |
| **不需要人一直介入** | `nlnotes write` / `write-group` 自动驱动模型:写 → 本地门禁校验 → 错误回灌 → 重写,直到通过 |
| 原版英文 PDF 保持现状 | 全流程**只读打开** PDF,产物一律写到 `build/` 与 `notes/`;自测用例专门校验 PDF 的大小与修改时间未变 |

## 2. 整体架构

```
D:\NetworkLessons\All-Courses-v3.0        ← 只读,永不改动
        │
        │  ① scan        递归扫描目录树
        │  ② audit       PDF 体检,剔除扫描件 / 加密 / 乱码文件
        ▼
   build/manifest.json + build/audit.md   每个 PDF 一条记录 + 镜像输出路径 + 可用性判定
        │
        │  ③ extract     PyMuPDF 只读打开(可选 OCR 拓扑图文字)
        ▼
   build/extract/<id>/                    分页文本 / 拓扑图 / 图注 / 标题层级 / CLI 块
        │
        │  ④ tasks       组装"自包含任务包"
        ▼
   build/tasks/<id>/TASK.md + 原文 + 图清单 + 术语表 + schema
        │
        │  ⑤ write       ★ 唯一花钱的一步(也可人工/Cursor 代劳)
        │                 写 → 校验 → 错误回灌 → 重写,直到通过
        ▼
   build/tasks/<id>/OUTPUT/note.json      结构化章节笔记(不是 Markdown)
        │
        │  ⑥ verify      9 组反臆想门禁(本地,免费)
        ▼
   build/reports/<id>.json                通过 / 逐条错误 + 修复建议
        │
        │  ⑦ visuals     渲染动画 GIF / 分步静态图 / mermaid
        │  ⑧ assemble    渲染 Markdown + 拷资源
        ▼
   notes/<与源目录完全相同的层级>/<课程>.md + assets/
        │
        │  ⑨ groups      按协议聚合(整个 OSPF / 整个 BGP)
        │  ⑩ write-group 撰写协议级面试复习笔记
        │  ⑪ build-group 校验(grounding 逐条比对)+ 渲染
        ▼
   notes/<方向>/<协议>/00-面试复习-<协议>.md
```

**两个关键设计**

1. **AI 不写 Markdown,只写结构化 JSON。**
   这样"排版好不好看"与"内容对不对"彻底解耦:
   排版由模板保证一致,内容由门禁保证不越界。

2. **两种笔记、两套标准。**
   *章节笔记*(每个 PDF 一份)零发散,严格锁死在本章原文;
   *协议级面试复习笔记*(每个协议一份)允许发散,但核心答案仍须有原文依据,
   工程经验必须显式放进"课程外扩展"区块。面试题放在协议级,是因为跨章素材
   才撑得起三层递进的追问深度。

## 3. 反臆想机制(方案的核心)

这是"严格遵守原文、不发散"能否落地的关键。共 9 组、40+ 条检查:

| 组 | 检查什么 | 能拦住什么 |
| --- | --- | --- |
| **S** 结构 | 是否符合 `note.schema.json`;`additionalProperties: false` | 私自加字段、缺字段、题目数量不够 |
| **P** 页码 | 引用页是否在 1~总页数之间 | 乱填页码 |
| **Q** 原文引用 | 每条 `text_en_quote`、`evidence_quote` 与**它声明的那一页**做模糊比对(默认阈值 90) | 改写原文、编造句子、页码写错(报告会指出正确页码) |
| **T** token 依据 | 中文字段里的英文词、IP、≥2 位数字,逐个回查原文 | 编造协议名 / 定时器数值 / IP / 命令 |
| **F** 发散措辞 | 禁用词表("笔者认为""生产环境通常""众所周知"……) | 夹带个人经验与课外内容 |
| **G** 图片 | `figure_id` 必须真实存在;引用比例达标;`labels_seen` 与 OCR 核对 | 编图 id、跳过拓扑图、编造图上文字 |
| **C** 配置 | `configs[].code` 必须逐字来自原文 | 手打一段"差不多"的 CLI 输出 |
| **V** 可视化 | 每张自制图 ≥1 条 `grounding` 原文引用;节点/链路引用合法 | 画出原文没有的拓扑与流程 |
| **X** 覆盖与测验 | 正文覆盖率 ≥80%;**知识点密度 ≥2.0 条/正文页**;题量/题型;中英双语纯度;**题目引用页 ⊆ 正文已讲页** | 挑简单段落糊弄、空洞概括、超纲出题、双语串行 |

协议级面试复习笔记另有一套门禁(宽松但仍可追溯):结构校验、`grounding` 逐条比对原文、核心答案 token 依据、中英双语纯度、连环追问必须正好三层、各区块数量下限、不确定表述(据说/我猜)一律拦下。
详见 `docs/04-验收与自测.md`。

两边同时约束:
**少写** → `X001` 覆盖度不足;**多写** → `T001`/`Q001`/`V001` 无原文依据。
所以 AI 既不能偷工,也不能加料。

### 关于拓扑图里的文字

PDF 的拓扑图是**图片**,里面的 `R1`、`Gi0/1`、`10.0.0.0/24` 不在文本层。
因此 AI 描述拓扑图时,必须先在 `figures[].labels_seen` 里登记它从图上读到的标签,
登记过的标签才被视为合法证据。开启 `figure_ocr` 后,工具会用 OCR 自动核对这些标签
(见 `docs/01-环境安装.md` 的可选项);未开启时会在报告里列出登记项,便于人工抽查。

## 4. 执行步骤

### 4.0 一次性准备

```powershell
# 1) 装 Python 3.10+ 与依赖
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2) 生成配置并改成你的课程路径
python -m nlnotes init
#    编辑 config/pipeline.json:
#      "source_root": "D:/NetworkLessons/All-Courses-v3.0"
#      "font_path":   "C:/Windows/Fonts/msyh.ttc"      ← 自制图的中文字体

# 3) 体检
python -m nlnotes doctor
```

`doctor` 会告诉你:路径对不对、依赖齐不齐、中文字体找到没有、
哪些可选工具缺失(缺失会自动降级,不影响出笔记)。

### 4.1 体检:先确认 PDF 能不能用

```powershell
python -m nlnotes scan
python -m nlnotes audit
```

`audit` 会逐个打开 PDF,判定三档并写出 `build/audit.md`:

- ✅ **可用** —— 有完整文本层,可正常抽取;
- ⚠️ **需注意** —— 能用但文字偏少 / 部分页是整页图片 / 没有内嵌位图;
- ❌ **剔除** —— 无文本层(扫描件)、有密码、文件损坏、提取出的文字大面积乱码。

被剔除的 PDF 会写进 `build/excluded.json`,**后续阶段自动跳过**,
报告里也会给出处理办法(扫描件需先用 ocrmypdf / Acrobat 转成可搜索 PDF)。

> 本流水线依赖 PDF 的文本层 —— 也就是"能在 PDF 里选中、能搜索"的文字。
> 这是硬前提:没有文本层,就没有可逐字引用的原文,反臆想门禁也就无从校验。

### 4.2 准备阶段(全自动,一条命令)

```powershell
python -m nlnotes prepare
```

等价于 `scan` + `extract` + `tasks`。跑完你会看到:

```
build/manifest.json                 全部 PDF 清单
build/extract/<id>/                 原文、拓扑图、CLI 块
build/tasks/<id>/TASK.md            每章一个任务包
```

想先小范围试跑(强烈建议):

```powershell
python -m nlnotes prepare --path OSPF --limit 3
```

### 4.3 撰写阶段(推荐全自动)

**做法 A:让流水线自己调模型跑完(不需要人盯着)**

```powershell
# 配置模型服务(任何兼容 OpenAI 协议的都行)与 Key
$env:NLNOTES_API_KEY = "你的key"

python -m nlnotes write --dry-run              # 先估成本,不发请求
python -m nlnotes write --path OSPF --limit 3  # 小批试跑,人工看效果
python -m nlnotes write                        # 全量跑,可中断,重跑自动续上
```

`write` 内部就是把人工会做的事自动化:写 → 本地门禁校验 → 把错误原样回灌 →
重写,直到通过或用完 `writer_max_rounds` 轮。**门禁在本地跑,不花钱**,
所以质量不依赖"模型很聪明",而依赖"校验很严格 + 允许重试"。

成本与模型选择见 [`docs/07-批量自动化与成本.md`](07-批量自动化与成本.md)。

**做法 B:让 Cursor / Claude Code 之类的会话逐章写**

先看下一步该做哪章:

```powershell
python -m nlnotes next --count 3
```

然后让 AI 工具执行:

1. 把 `prompts/00-system-中文笔记作者.md` 设为 system prompt / 项目规则;
2. 用 `prompts/10-章节笔记生成.md` 的模板发起任务,指向该章的 `build/tasks/<id>/`;
3. AI 读 `TASK.md` → 读原文 → **看图** → 写 `OUTPUT/note.json`;
4. AI 自己运行 `python -m nlnotes build --id <id>`,按报告修,直到通过
   (修订规则见 `prompts/40-修订循环.md`)。

在 Cursor 里最省事的说法:

> 读 `build/tasks/<id>/TASK.md` 并严格按它的要求产出 `OUTPUT/note.json`,
> 然后运行 `python -m nlnotes build --id <id>`,按报告逐条修到通过。
> 遵守 `prompts/00-system-中文笔记作者.md` 的全部铁律。

### 4.3 校验与出笔记

```powershell
python -m nlnotes build --id <pdf_id>      # 校验 + 渲染 + 组装
python -m nlnotes build                    # 全部已写完的章节一起来
python -m nlnotes verify --id <pdf_id> --show   # 只看报告
```

校验不通过默认**不生成**笔记(可用 `--force` 强制生成草稿,不推荐)。

### 4.4 协议级面试复习笔记(某个协议的章节都写完之后)

```powershell
python -m nlnotes groups --list        # 看有哪些协议分组、各自完成了几章
python -m nlnotes groups               # 生成面试复习任务包
python -m nlnotes write-group          # 自动撰写(或让 Cursor 读 TASK.md 写)
python -m nlnotes build-group          # 校验 + 渲染
```

产出 `notes/<方向>/<协议>/00-面试复习-<协议>.md`,包含:

1. **知识体系图** —— mermaid 图把各章串起来 + 复习顺序及理由;
2. **跨章必须掌握清单** —— 面试前必须张口就答的;
3. **高频必考基础/原理题** —— 每题带**高分答题模板**(开场结论 / 分段展开 / 收尾)
   与**得分要点**(面试官逐条打分);
4. **场景化面试题** —— 具体到能动手分析的现场 + **解题框架**(排查/推导顺序);
5. **面试官连环追问** —— 每组正好三层:是什么 → 为什么/怎么做 → 边界与代价,
   每层标注"面试官想验证什么";
6. **避坑指南** —— 用候选人原话写出典型错误说法,再说清错在哪、正确怎么说。

发散内容会被渲染成独立的「🔶 课程外扩展」区块,与有原文依据的核心答案分开,
你一眼就能分清哪些是课程结论、哪些是工程经验。

### 4.5 查看进度

```powershell
python -m nlnotes status --detail
python -m nlnotes index          # 重建 notes/README.md 导航索引
```

`notes/README.md` 会按课程方向列出每一章的状态:
⚪ 未开始 / 🔵 待撰写 / 🟠 待组装 / 🟡 待修正 / ✅ 已校验。

### 4.6 批量跑法

Windows 一键脚本:

```powershell
.\scripts\Run-Pipeline.ps1 -SourceRoot "D:\NetworkLessons\All-Courses-v3.0" -Filter OSPF
```

它会跑完准备阶段,并把"接下来要写哪几章"打印出来给 AI。
写完 `note.json` 后再跑:

```powershell
.\scripts\Run-Pipeline.ps1 -BuildOnly
```

## 5. 产出长什么样

单章笔记(`notes/<方向>/<子方向>/<课程>.md`)固定结构:

**A. 章节笔记**(每个 PDF 一份,零发散)

```
YAML front matter(标题 / 源文件 / 页数 / 图数 / 覆盖率 / 是否已校验)
一、本章概要          ← 4~8 句 + 本章边界声明
二、术语速查          ← 中英对照 + 原文页码
三、正文精讲
     1. 小节标题(中/英)  p.x
        - 知识点(中文)   <sub>(p.x)</sub>
          > 原文:英文原句            ← 逐条可回溯
          深入说明:机制怎么运作、成立前提、例外情况   ← detail_zh
        图 · 原文拓扑图 + 中文讲解 + 图中可见标签
        自制图解 · 动画 GIF + 分步静态图 + 原文依据(可折叠)
        配置 / 命令(逐字引用)+ 逐行中文注解
四、关键要点回顾
五、费曼学习法检验 / Feynman Review
     第 1 步:用大白话复述(≥200 字,有主线)
     第 2 步:必须掌握的关键知识点(为什么必须掌握 + 记忆抓手)
     第 3 步:本章难点(难在哪 / 为什么容易卡住 / 怎么突破 / 对照哪张图)
     第 4 步:自测题(每题中英双语)
     第 5 步:常见盲点
     第 6 步:复习计划
     参考答案(折叠,中英双语 + 原文依据 + 自评要点)
附录:可信度说明(引用通过率 / AI 图声明 / 源 PDF 未修改)
```

**B. 协议级面试复习笔记**(每个协议一份,允许发散但分栏)

```
YAML front matter(覆盖章节数 / 各区块题量 / grounding 通过率)
覆盖的章节        ← 可点击跳回各章笔记
一、知识体系图 / Knowledge Map        ← mermaid + 复习顺序
二、必须掌握清单 / Must Master        ← 跨章,附原文出处
三、高频必考基础 / 原理题             ← 高分答题模板 + 得分要点(中英对照表)
四、场景化面试题 / Scenario           ← 场景 + 解题框架 + 参考答案 + 得分要点
五、面试官连环追问 / Follow-up        ← 三层递进,每层含考察意图
六、避坑指南 / Common Pitfalls        ← 错误说法 / 错在哪 / 正确说法
七、面试前 5 分钟自查
附录:可信度说明(grounding 通过率 / 扩展内容声明)
```

题目与答案全部中英双语;每个区块下方标注原文出处;
课程外的工程经验统一收进「🔶 课程外扩展」折叠区块。

图片与动画放在同目录 `assets/<pdf_id>/`,用**相对路径**引用,
Obsidian / Typora / VS Code / GitHub 都能直接看图看动图。

## 6. 为什么这套方案能"直接实施成功"

1. **AI 的输出面被收窄成一个 JSON**,有 schema 约束,不会跑偏成散文。
2. **每一条错误都带定位与修复建议**,AI 能自己闭环修订,不需要人盯着。
3. **不依赖任何付费服务也能完整跑通**:
   动画是纯 Pillow 自绘;mermaid / graphviz / ffmpeg / OCR / AI 图全部可选,
   缺了自动降级并在笔记里说明,不会中断。
4. **增量可续**:PDF 用 SHA-256 缓存,重跑不会重复劳动;
   `status` / `next` 让上千个 PDF 的长期工程有明确的推进顺序。
5. **可以完全不用人介入**:`nlnotes write` / `write-group` 自己完成
   "写 → 校验 → 修" 的循环;只有调参和少数失败章节需要人看一眼。
6. **端到端自测已通过**:`python tests/run_e2e.py` 会造两份合成 PDF(一份正常、
   一份扫描件),跑完整流水线(含体检、分组、面试笔记),用**本地假 LLM 服务**
   验证自动撰写闭环,并用 **27 个"臆想反例"**验证门禁真的拦得住
   (见 `docs/04-验收与自测.md`)。

---

## 7. 建议的推进节奏

1. 先用 `--path <某个协议>` 挑 1 章跑通全流程,人工通读笔记,确认风格符合预期。
2. 若想调整风格,改的是 `templates/note.md.j2`(排版)和 `prompts/`(写法),
   **不要动门禁阈值**。
3. 按方向分批推进(先 Switching,再 IGP,再 BGP……),每批跑完检查 `notes/README.md`。
4. 术语译名不统一时,补 `glossary/terms.csv`,后续章节会自动统一。
