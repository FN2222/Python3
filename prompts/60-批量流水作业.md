# 批量流水作业提示词 —— 一条消息做完一整批章节

> 用途:在 Cursor 里让 Grok 4.6(或其他模型)**一条消息连续做完 N 章**,
> 而不是你一章一章下发指令。这是"用 Cursor 跑"时最接近全自动的方式。
>
> 真正的无人值守请用 `nlnotes write`(直接调 API),见
> [`docs/07-批量自动化与成本.md`](../docs/07-批量自动化与成本.md)。

---

## 0. 新开一个会话,只贴本文件能不能开工?

**能,但不要把本文件从头到尾全贴进去。** 本文件后半是给你看的操作说明
(进度查询、面试复习、换协议、何时停下来调参),贴给新会话会让它一次想做太多事。

新会话**不需要**你再贴:

- 旧聊天记录
- `prompts/00-system-中文笔记作者.md` 全文(它会自己读仓库里的文件)
- 课程 PDF、方案文档、`docs/` 里的长文
- 面试复习那段(章节全部写完后再发第三节)

Cursor 打开本机 `D:\Python3` 后会自动读 `AGENTS.md` 和 `.cursor/rules/`,
铁律已经在项目里,不用你口头交代。

### 开工前你自己先确认这 3 件事

在**本机 PowerShell**(不是云端 bash)里跑:

```powershell
cd D:\Python3
.\.venv\Scripts\python.exe -m nlnotes next --count 1
```

| 结果 | 含义 | 怎么办 |
| --- | --- | --- |
| 打出一个 `pdf_id` + `build\tasks\...` 路径 | 任务包已就绪 | 可以开新会话写笔记 |
| 没有任何输出 / `没有待写章节` | 准备阶段还没跑,或这一批已经写完 | **先不要开写作会话**。回到 [`docs/08-本机上手-用Cursor跑.md`](../docs/08-本机上手-用Cursor跑.md) 第 2 节跑 `prepare` |
| `unrecognized arguments` | 本地代码版本偏旧 | 先更新代码(见 `docs/08` 的 1.1.5),不要硬跑 |
| `课程根目录不存在` | `config\pipeline.json` 的 `source_root` 写错 | 先修配置 |

另外两点:

1. **必须是本机 Cursor 打开 `D:\Python3` 的 Agent 模式**(能读写文件、能跑终端)。
   不要开成 Ask 模式,也不要开 Cloud Agent —— 云端机器没有你的 `D:\NetworkLessons`。
2. 新会话首条**只贴下面第一节代码框**,不要连同第二~五节一起发。
   `prompts/61-继续下一批.md` 是同一会话续写用的短指令,新会话不要只贴 61。

## 一、批量撰写章节笔记(新会话首条:只复制这个代码框)

`N` 建议 5(一条消息做 5 章),太多会因为上下文变长而降质。

```
你现在是 nlnotes 的章节笔记撰写员。本会话只写章节笔记,不要改代码、不要改配置、不要做面试复习笔记。

== 先做 30 秒体检,任一失败就停下来告诉我,不要开始写 ==
1. 确认当前目录是本仓库根(能看到 nlnotes\ 和 prompts\)
2. 跑: .\.venv\Scripts\python.exe -m nlnotes next --count 1
   - 能打出 pdf_id → 继续
   - 打不出 / 报错 → 原样贴输出,停止。不要自己去 scan/extract/改配置

== 环境约定 ==
- 一律用 .\.venv\Scripts\python.exe 调用 Python,不要用 Activate.ps1
- 课程 PDF 只读,不要改动源目录里的任何文件
- 不要修改 config/ 下的任何配置,不要下调门禁阈值
- 不要修改 prompts/、schemas/、nlnotes/、templates/
- 笔记只写到 build/tasks/<ID>/OUTPUT/note.json,Markdown 由 nlnotes build 渲染

== 你必须遵守的写法 ==
先读一次 prompts/00-system-中文笔记作者.md,把它当作贯穿本批的铁律。
写每一章前再读该章的 TASK.md。原文依据以 source-text.md 为准。
错误码改法见 prompts/40-修订循环.md。可视化规格见 prompts/20-可视化设计.md。
费曼出题规范见 prompts/30-费曼测验.md。
这些文件都在仓库里,直接读,不要让我再贴一遍。

首批 OSPF 5 章已经验证过的高频翻车,写的时候直接避开:
- quote 必须同页连续,禁止跨页、禁止用 ... 拼接 show 输出里不相邻的行
- 不要自行把全称缩成 ABR,也不要把 DR 展开成本章没出现的 Designated Router
- 不要把 255.255.255.0 改写成 /24,中文里不要写 vs,讲解里不要写 figure_id
- points[].kind 不要填 process(那是题目的 type);why_zh≥15 字,answer_zh≥25 字
- 题目 type 不要填 command(命令题用 config);why_hard_zh/how_to_break_zh ≥ 20 字
- 密度目标 ≥ 3.0,mechanism/step/caveat/definition 必须有 detail_zh;不要贴着 2.0 停

== 每一章的固定流程 ==
1. 取任务:
     .\.venv\Scripts\python.exe -m nlnotes next --count 1 --ids-only
   把输出的那个 id 记为 <ID>。如果没有输出,说明本批已全部完成,跳到汇报。

2. 读齐输入(缺一不可):
     build/tasks/<ID>/TASK.md          ← 本章要求与阈值,以它为准
     build/tasks/<ID>/source-text.md   ← 原文全文,页码是 [[p.N]]
     build/tasks/<ID>/outline.md
     build/tasks/<ID>/figures.md       ← 可用图清单
     build/tasks/<ID>/glossary.md      ← 术语统一译名
     build/tasks/<ID>/codeblocks.md
     build/tasks/<ID>/note.schema.json

3. 看图:figures.md 里列出的每张图片都要打开看一遍,
   把图上读到的文字逐字登记到 figures[].labels_seen。
   (如果 figures.md 里已经有 OCR 识别出的文字,以它为主,再补你看到的)

4. 写 build/tasks/<ID>/OUTPUT/note.json
   - text_en_quote 必须从 source-text.md 复制粘贴,不能凭理解改写
   - 不要写原文没有的协议、命令、数值、默认值、工程经验
   - 知识点要详尽:机制性的点补 points[].detail_zh,不要一层标题式概括

5. 校验并修订:
     .\.venv\Scripts\python.exe -m nlnotes build --id <ID>
   不通过就读 build/reports/<ID>.json 的 errors,
   按 prompts/40-修订循环.md 的错误码对照表逐条修 note.json,然后重跑。
   最多修 5 轮;5 轮还不过就记下来,跳过这一章继续下一章。

6. 回到第 1 步,直到做完 5 章(或没有待做章节)。
   一章一章来,上一章门禁通过再进入下一章,不要并行开多章(页码会串)。

== 本批做完后汇报 ==
- 每章分别用了几轮才通过
- 有没有反复出现的同类错误码(这说明提示词或参数要调,而不是每章硬修)
- 有没有跳过的章节,以及卡在哪个错误上
- 最后跑一次并把输出贴出来:
    .\.venv\Scripts\python.exe -m nlnotes stats --detail
```

做完一批就把上面那段**原样再发一次**(同一会话或新会话都行),
它会自动接着下一批 —— `next` 只列**还没有 note.json** 的章节。
同一会话续写也可以改发更短的 [`prompts/61-继续下一批.md`](61-继续下一批.md);
**新开的会话不要只贴 61**,61 依赖「规则与上一批相同」,新会话没有上一批。

不想每批手动粘:Grok 还在写时把 61 粘进输入框按 Enter **排队**;
或 `python -m nlnotes watch --enable` 打开自动续写(Cursor stop hook,默认关闭)。
详见 `docs/08-本机上手-用Cursor跑.md` 第 4.1 节。

**重要:**DeepSeek / `write` 失败留下的 `note.json` 也算"已经写过",`next` 会跳过它们往后面取。
所以第 6、7 章(MD5 / SHA)这种"已撰写但未过门禁"的章,必须**点名 id 补写**,不能靠 `next`。

## 一.1 补写未过门禁的章(例如第 6、7 章),然后继续后面

当前 Grok 如果正在写某一章:先把**这一章**跑到 `build` 通过(或满 5 轮记下错误),然后停,不要再 `next`。
不要新开第二个窗口同时跑 `next`(会抢同一章)。把下面整段粘进**同一个**对话:

```
先停下来,不要再运行 next。

原因:nlnotes next 只看有没有 note.json,不看过没过门禁。
DeepSeek 给 OSPF MD5 / SHA 两章留下了未通过的 note.json,所以它们被跳过了。

== 现在立刻补这两章 ==
1. 跑:
     .\.venv\Scripts\python.exe -m nlnotes status --detail
   找出标题含 MD5 和 SHA Authentication、状态是「已撰写」而不是「已校验」的两章,记下它们的 id。
   也可以跑 .\.venv\Scripts\python.exe -m nlnotes next
   (新版本会在顶部列出未通过的 id)。

2. 覆盖现有 note.json,从任务包重写,不要沿用 DeepSeek 那份。
   一章一章来,每章跑到门禁通过再进入下一章。流程与 prompts/60 单章流程相同。
   认证章特别容易翻车,写的时候直接避开:
   - questions[].type 禁止填 command(命令/配置题填 config)
   - points[].kind 禁止填 process(流程点填 step)
   - 不要把 LSA 展开成 Link State Advertisement,也不要把 DR 展开成 Designated Router
   - 图上的 IP/网段必须先写入该图 labels_seen
   - text_zh ≥ 10 字; why_hard_zh 与 how_to_break_zh ≥ 20 字; answer_zh ≥ 25 字
   - quote 必须同页连续,禁止跨页、禁止用 ... 拼接不相邻的命令行

3. 两章都通过后,再按 prompts/60 用 next 继续后面还没写的章(第 9 章及以后)。
   已通过的第 1–5 章、以及你已经写完并通过的第 8 章,next 会自动跳过。
   本消息只做这两章补写,不要同时开下一批评列。
```

## 三、这个协议的章节全部写完后:出面试复习笔记

**等 `status` 显示该协议章节全部通过后再发**,不要和第一节塞进同一条消息。

```powershell
.\.venv\Scripts\python.exe -m nlnotes build          # 确认全部章节笔记都已生成
.\.venv\Scripts\python.exe -m nlnotes groups --list  # 确认只有 1 个分组
.\.venv\Scripts\python.exe -m nlnotes groups
```

然后把下面这段粘给 AI(注意系统提示词换成 `50-面试复习.md`,规则和章节笔记不同):

```
请产出这个协议的面试复习笔记。本会话不要写章节笔记、不要改代码、不要改配置。

先读 prompts/50-面试复习.md —— 这是本任务的铁律,**不要**用章节笔记那份。
```

### 三.1 面试复习写早了(缺了几章),要整份重写

旧的 `interview.json` **不能**在上面打补丁 —— 任务包里的 `chapters.md` 还是缺章时的素材,
门禁对「有章未纳入」默认只警告,补几个 id 就能混过去。

正确顺序:先确认缺的章节笔记已经门禁通过 → 重建分组任务包 → 删掉旧 `interview.json` → 整份重写。

把 [`prompts/62-重写面试复习.md`](62-重写面试复习.md) **整份**粘给 Grok 4.6(新开一个会话更干净,避免它沿用旧稿上下文)。

## 五、什么时候该找人调参而不是继续硬跑

出现下面任一情况,先停下来:

- **同一个错误码在多章反复出现** —— 说明提示词或抽取参数需要调,不是模型的问题
- **`stats` 里知识点密度贴着门槛(2.0~2.3)** —— 说明笔记在敷衍,该加强提示词
- **多章卡在 5 轮仍不通过** —— 可能是这批 PDF 的排版特殊,需要调抽取参数
- **`G003` 图片引用不足反复出现** —— 抽取出的"图"里可能有误判,人工抽查
  `build/extract/<id>/figures/` 里的 PNG
