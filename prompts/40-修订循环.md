# 修订循环 —— 门禁报错后怎么改

> 这是 AI 自我修订的操作手册。核心原则:**改笔记,不改门禁。**

## 一、循环流程

```
写 note.json
   ↓
python -m nlnotes build --id <pdf_id>
   ↓
通过? ── 是 ──> 完成,进入下一章
   │
   否
   ↓
读 build/reports/<pdf_id>.json 的 errors
   ↓
按错误码逐条修 note.json(每条错误都带 where 定位和 fix 建议)
   ↓
回到 build
```

**最多允许自动重试 5 轮。** 5 轮还过不了,把剩余错误列出来交给人工判断,
不要为了通过而删内容或放宽阈值。

## 二、错误码速查

| 码 | 含义 | 正确改法 | 错误改法(禁止) |
| --- | --- | --- | --- |
| `S001` | 不符合 schema | 对照 `note.schema.json` 补齐/改正字段 | — |
| `S002`~`S004` | id 重复 | 改成唯一 id | — |
| `S005` | `pdf_id` 不匹配 | 改回任务包给的 pdf_id | — |
| `P001` | 页码越界 | 对照 `[[p.N]]` 改页码 | 随便填个小数字 |
| `Q001` | 知识点引用与原文不匹配 | 回原文**逐字复制**;报告会告诉你它其实在第几页 | 把 quote 改短来蒙过阈值 |
| `Q002` | 题目 `evidence_quote` 与原文不匹配 | 同上 | — |
| `Q010`(警告) | 英文小节标题匹配度低 | 换成原文真实标题或关键短语 | — |
| `T001` | 中文里出现原文没有的技术词/数字 | 删掉,或改用原文的说法;若是拓扑图上的标签,登记到 `labels_seen` | 往 `token_whitelist` 里加专业术语 |
| `T002` | `terms` 里的术语原文没出现 | 删掉该术语 | — |
| `T003`(警告) | 译名与术语表不一致 | 改用术语表译名 | — |
| `F001` | 出现发散措辞 | 删掉整句 | 换成同义的发散说法 |
| `G001` `G002` | `figure_id` 不存在 | 对照 `figures.md` | 编一个 id |
| `G003` | 引用的原文图太少 | 把剩下的拓扑图补进对应小节并写讲解 | 关掉 `require_figure_when_available` |
| `G010` | `labels_seen` 在 OCR 结果里找不到 | 重新看图,照抄图上文字 | 乱填标签来放行 token |
| `C001` `C002` | 配置块页码错/不是原文逐字内容 | 从 `codeblocks.md` 重新复制 | 手打一段"差不多"的输出 |
| `C003` | 注解引用的行不在配置块里 | `line` 必须是 `code` 里的原样一行 | — |
| `V001` | 自制图的 `grounding` 不是原文 | 换成原文真实句子;若找不到出处,说明这张图超纲了,**删掉这张图** | 硬凑一句 |
| `V010`~`V017` | 可视化规格不完整 | 按 `20-可视化设计.md` 补齐 | — |
| `X001` | 内容覆盖度不足 | 给未覆盖的页补小节/知识点 | 在 `pages` 里硬加页码却不写内容 |
| `X002` `X004` | 题目数量/类型不足 | 补题(仍须有原文依据) | 复制已有题目改几个字 |
| `X005`~`X008` | 中英双语字段串了 | 修正对应字段 | — |
| `X011` | 题目引用了正文没讲的页 | 要么正文补上,要么把题改回覆盖范围内 | — |

## 三、几个高频陷阱

### 1. `Q001` 引用匹配度不够(首批 OSPF 最常见)

常见三种写法都会掉到阈值以下,不要用:

- 一条 quote 里出现了两个页码,或跨越 `[[p.N]]` 边界
- 用 ` ... ` 把不相邻的两段(尤其是 `show` 命令输出里隔开的行)拼成一句
- 把原文改写成"差不多"的句子

正确做法:回 `source-text.md` **同一页连续复制**;需要两处原文就写两条 point。
若报告写"该句在第 N 页",只改页码即可。

### 2. `T001` 报出的是拓扑图里的设备名

例如中文写了"R2 通过 Gi0/1 连到 R3",但原文文本层没有这些字。
正确做法:在引用那张图的 `figures[].labels_seen` 里登记 `R2`、`Gi0/1`、`R3`。
如果这些名字在图上也找不到,那就是你编的,删掉。

### 3. `T001` / `T002` 报的是缩写、掩码或术语全称(首批 OSPF 真实出现过)

- 原文只写 `area border router` → 中文也写全称,不要自行改成 `ABR`
- 原文只写 `DR` / `BDR` → `terms[].en` 就登记 `DR` / `BDR`,不要展开成
  本章没出现的 `Designated Router`
- 原文写 `255.255.255.0` → 不要改成 `/24`(反向也不行)
- 中文字段不要写 `vs`(写成"与""对比")
- `explain_zh` 里不要出现 `fig-p001-1` 这种 figure_id,id 只放在字段里

### 4. `S001` schema 不合格(首批 OSPF 真实出现过)

- `points[].kind` **没有** `process` 这个值;`process` 只属于 `feynman.questions[].type`
- `must_master[].why_zh` 至少 15 字;`questions[].answer_zh` 至少 25 字

### 5. `T001` 报出的是通用词

例如 `Markdown`、`OSI`。这类确实与课程内容无关的通用词,
可以加进 `config/pipeline.json` 的 `token_whitelist`。
**但协议名、命令、数值一律不许加白名单。**

### 6. 反复过不了 `X001` 覆盖度

通常是漏掉了原文中间的几页。用 `content_pages`(在 `context.json` 里)
对照你的 `sections[].pages`,找出缺哪几页,针对性补内容。

### 7. 想删内容来过门禁

**不允许。** 删掉真实内容会触发 `X001` 覆盖度不足。门禁的设计目标是
"既不能少写,也不能多写",两边同时约束。

## 四、自检清单(提交前自己走一遍)

- [ ] 每个 `text_en_quote` 都是我从 `source-text.md` **同一页连续**复制的,没有跨页、没有拼接命令行
- [ ] 我打开看过 `figures.md` 里的每一张图,`labels_seen` 是照抄图上的文字
- [ ] 中文里的每个英文词、每个数字,我都能指出它在原文第几页;没有擅自缩写或换算掩码
- [ ] `points[].kind` 没有误填 `process`;mechanism/step/caveat/definition 都有 `detail_zh`
- [ ] 知识点密度明显高于 2.0(目标 ≥ 3.0)
- [ ] 每个自制图的 `why_zh` 都说清了"原文哪句话难懂"
- [ ] 每道题的答案都能在 `evidence_quote` 里找到依据;`answer_zh` ≥ 25 字
- [ ] `q_en` / `answer_en` 里没有中文,`q_zh` / `answer_zh` 里有中文
- [ ] 我没有写任何"原文没讲但我知道"的内容
